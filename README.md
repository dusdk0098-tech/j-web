# J웹(제이웹)

건설현장 안전관리 웹앱의 초기 시험 구현입니다. 현재는 가상 데이터로 기능을 살펴보는 단계이며 실무 운영에 사용할 수 없습니다.

J웹 자체 코드는 [MIT 라이선스](LICENSE)로 제공합니다. 제3자 의존성에는 각각의 라이선스가 적용됩니다.

## 실행

Node.js 22.13 이상에서 의존성을 설치합니다.

```sh
npm install
```

검증은 `npm test`로 실행합니다. 현장과 출입자, 문서, 결재 이력은 `data/`의 SQLite 파일에 저장되고 Git에 포함되지 않습니다. Node.js 버전에 따라 SQLite 실험 기능 경고가 표시될 수 있습니다.

서버는 Node.js HTTP API를 제공하고 브라우저는 JSON 요청과 파일 첨부 요청으로 통신합니다. 기본 데이터베이스는 `data/jweb.sqlite`이며 `JWEB_DATA_DIR`을 설정하면 해당 폴더에 같은 파일명으로 저장합니다. 첨부파일과 시험 서명, 유효한 시험 근로자 세션의 해시도 이 데이터베이스에 저장됩니다. 별도 클라우드 DB나 자동 백업은 구성하지 않습니다.

### 데이터 백업과 별도 복원

백업은 실행 중인 SQLite의 일관된 사본을 만들고 무결성을 검사합니다. 백업과 복원 파일에서는 근로자·직원·발주처 로그인 세션을 지우므로 사본을 사용할 때 다시 로그인해야 합니다. 복원본은 현장 접속 주소를 새로 만들고 이전 가입 초대를 중지하며 현장 가입을 닫습니다. 관리자는 복원 후 새 QR을 출력하고 필요한 경우 가입을 다시 열어야 합니다. 원래 데이터베이스와 현재 로그인·QR은 바뀌지 않습니다. 백업에는 현장 자료·첨부파일·계정 해시와 접속 정보가 포함되며 암호화되지 않으므로 접근이 제한된 저장소 밖의 폴더에 보관하세요.

아래 예시는 폴더를 미리 만든 뒤 PowerShell에서 실행합니다. 서버가 `JWEB_DATA_DIR`을 사용한다면 백업을 실행하는 터미널에도 같은 값을 설정하세요. 대상 파일이나 SQLite 보조 파일이 이미 있으면 덮어쓰지 않습니다. 중단되거나 검사에 실패한 사본은 사용하지 마세요.

```powershell
npm run backup -- 'C:\path\backup\jweb-backup.sqlite'
npm run restore -- 'C:\path\backup\jweb-backup.sqlite' 'C:\path\restored-data'
$env:JWEB_DATA_DIR = 'C:\path\restored-data'
$env:PORT = '4174'
$env:JWEB_ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', (Read-Host '시험 관리자 암호' -AsSecureString)).Password
npm start
```

복원 대상은 기존 `jweb.sqlite`가 없는 별도 폴더여야 합니다. 위 예시는 기존 서버와 다른 포트로 복원 서버를 시작하며 `http://127.0.0.1:4174/`에서 내용을 확인합니다. 해당 포트가 사용 중이면 다른 포트로 바꿔 주세요. 복원은 해당 시점 이후 변경을 포함하지 않으며 계정과 권한도 백업 당시 상태이므로 다시 확인해야 합니다. 사본 완성 후 같은 폴더의 임시 파일에서 대상 파일로 연결하므로 파일 연결을 지원하는 파일시스템이 필요합니다. 실제 운영이나 암호화 백업을 제공한다는 뜻은 아닙니다.

동시에 저장하는 요청이 있으면 잠금이 발생한 각 SQLite 작업은 최대 3초 기다립니다. 계속 사용 중이면 저장 실패를 알리며, 사용자가 내용을 확인한 뒤 다시 시도할 수 있습니다. 대기 중에는 같은 서버 프로세스의 다른 요청도 지연될 수 있습니다.

PowerShell에서 12자 이상의 시험 관리자 암호를 입력하고 실행한 뒤 이 컴퓨터의 브라우저에서 `http://127.0.0.1:4173/`을 엽니다. 암호를 설정하지 않으면 서버가 시작되지 않습니다.

```powershell
$env:JWEB_ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', (Read-Host '시험 관리자 암호' -AsSecureString)).Password
npm start
```

기본 관리자는 모든 현장을 관리합니다. 별도 시험 직원 계정은 본인이 작성한 업무 문서와 지정된 결재·참조 문서를 볼 수 있습니다. 서버를 재시작하면 관리자 세션은 만료되며, 결재자와 근로자 세션은 최초 로그인 후 최대 8시간 동안 유지됩니다. 일반 업무의 다중 사용자 권한과 안전한 외부 배포는 아직 지원하지 않습니다.

휴대전화 QR 시험을 위한 HTTPS 중계 주소는 `JWEB_PUBLIC_ORIGIN`에 경로 없이 설정할 수 있습니다. 예: `https://example.test:8443`. 이 경우 서버는 계속 `127.0.0.1`에서만 수신하며 지정된 호스트와 HTTPS 출처만 허용하고 QR에 지정된 주소를 넣으며 세션 쿠키에 Secure를 추가합니다. 주소 설정만으로 중계, 인증서 또는 방화벽이 만들어지지는 않습니다. 인증·권한·운영 보안이 미완성이므로 가상 자료만 사용하고 외부 공개나 실사용에 이용하지 마세요.

내장 시험 중계는 별도의 터미널에서 `npm run proxy`로 실행합니다. 서버와 중계에 같은 `JWEB_PUBLIC_ORIGIN`과 `PORT`를 설정하고, 중계에는 `JWEB_TLS_CERT`와 `JWEB_TLS_KEY`에 인증서와 개인키 파일 경로를 지정합니다. 중계는 기본적으로 이 컴퓨터에서만 수신합니다. 휴대전화 시험 시 `JWEB_PROXY_BIND`에 이 컴퓨터의 접근 가능한 IP 주소를 지정해야 합니다. 중계 포트는 HTTPS 주소에 지정하며 서버 포트와 달라야 합니다. 중계는 시작할 때 인증서의 대체 이름이 접속 주소와 맞는지, 유효 기간과 개인키가 맞는지 확인합니다. 이 검사는 휴대전화의 인증서 신뢰를 보장하지 않습니다. 주소의 이름이 휴대전화에서 해당 IP로 연결되고 인증서가 휴대전화에서 신뢰되어야 합니다. 네트워크와 방화벽도 해당 연결을 허용해야 합니다.

인증서와 개인키는 직접 준비하고 저장소 밖에 보관하세요. 이 중계는 접속 URL을 기록하지 않지만, 다른 중계나 서버를 사용할 때도 가입 토큰이 포함된 전체 URL을 접근 기록에 남기지 않도록 설정해야 합니다. 서버와 중계를 시작한 뒤에는 HTTPS 주소로 관리자 화면을 열어 시험 QR을 만듭니다.

예를 들어, 다음 예시의 주소·IP·파일 경로를 실제 준비한 값으로 바꾼 뒤 PowerShell 두 개에서 각각 실행합니다. 두 터미널의 주소는 같아야 합니다.

```powershell
# 첫 번째 터미널: 시험 서버
$env:JWEB_PUBLIC_ORIGIN = 'https://example.test:8443'
$env:JWEB_ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', (Read-Host '시험 관리자 암호' -AsSecureString)).Password
npm start
```

```powershell
# 두 번째 터미널: HTTPS 시험 중계
$env:JWEB_PUBLIC_ORIGIN = 'https://example.test:8443'
$env:JWEB_PROXY_BIND = '192.168.1.10'
$env:JWEB_TLS_CERT = 'C:\path\certificate.pem'
$env:JWEB_TLS_KEY = 'C:\path\private-key.pem'
npm run proxy
```

서버가 생성하는 현장 및 가입 QR 이미지는 512×512 픽셀이며 네 칸의 흰색 여백을 포함합니다. 자동 시험은 OpenSSL을 사용할 수 있을 때 임시 인증서로 이 컴퓨터의 로컬 주소와 사용 가능한 네트워크 IP에 HTTPS 중계를 만들고 가상 가입 QR의 판독, 가입 및 로그인 API를 확인합니다. OpenSSL이나 사용할 IP가 없으면 해당 시험은 건너뜁니다. 이 시험은 실제 휴대전화나 운영용 인증서를 검증하지 않습니다.

## 현재 가능한 시험

- 현장 추가 및 현장별 출입자 등록·수정, 구분·소속·직종·등록 기간과 가상 생년월일·전화번호·메모 검색, 검색 결과 엑셀 내려받기. 선택한 출입자 최대 20명의 가상 가입 정보·보호구 기록·시험 서명과 첨부서류 이름을 미리보거나 인쇄할 수 있습니다. 조회 후 이름·구분·소속·직종·메모가 바뀌면 다시 선택해야 하며 가입·보호구·첨부는 미리보기 조회 당시 기록입니다. 실제 개인정보, 브라우저 및 인쇄는 미검증입니다.
- 현장별 협력사 회사명·공종 등록 및 수정 (시험용 독립 목록)
- 등록 목록에서 미사용 협력사를 삭제할 수 있습니다. 같은 현장의 출입자 소속 이름이나 문서의 협력사 이름·번호로 사용 중이면 삭제하지 않습니다. 이름·공종을 다시 확인하고 잠금을 얻은 뒤 사용 여부와 관리자 세션을 검사합니다. 삭제는 등록 목록과 가입 후보에서 숨기는 방식이며 기존 번호는 재사용하지 않습니다. 이는 독립적인 시험 규칙으로 실제 화면은 미검증입니다.
- 로컬 시험용 단일 관리자 로그인
- 가상 출입자의 날짜별·월별 출역 등록·취소와 현장별 인원 집계, 근로자·직종·소속별 기간 합계 및 날짜별 소속·직종·이름 검색
- 현장별 30일 가입 QR 생성·인쇄·중지와 지속적인 현장 로그인 QR. 관리자가 현장 QR 가입을 별도로 열면 같은 QR로 30일간 가상 신규 가입과 기존 로그인을 할 수 있으며 모든 가입 QR 중지 시 함께 닫힘 (화면 및 실제 휴대전화 미검증)
- 현장별 선택적인 시험 위치 확인과 날짜별 위치 기록 조회·삭제. 설정된 반경과 정확도에 맞는 기기 위치만 시험 로그인·QR 재접속의 출역에 사용합니다. 실제 휴대전화에서의 위치 확인은 검증하지 않았습니다.
- 현장별 가상 식당명과 식비·간식비·부가세 금액 등록 및 수정. 식비 변경 시 식비의 10%를 내림하여 부가세로 입력하고 직접 수정할 수 있으며 식비와 부가세 합계를 표시합니다. 근로자별 식대 명세서 합계에는 부가세가 포함되지 않습니다.
- 날짜별 가상 출입자의 조식·중식·석식·간식 체크, 당시 식당명·단가와 식사 부가세 보존 및 근로자별 월간 기록 변경. 이전 기록과 간식 부가세는 미기록으로 두며, 식당별 명세서에서 기록된 부가세와 포함 합계를 표시합니다. 근로자별 합계는 부가세를 제외합니다.
- 직영과 현장관리자 가상 출입자의 신규 출역에 각각 설정한 가상 식당 자동 적용 (현장관리자는 출입자 구분이 정확히 현장관리자인 기록이며 관리자 계정과 자동 연결되지 않음)
- 일별 출역 목록에서 출역자의 조식·중식·석식·간식 가상 식당을 선택하거나 기록 삭제. 같은 식당을 유지하면 기록 당시 단가도 유지하며, 식당을 변경하면 새 단가로 저장됩니다.
- 월간 가상 식대 명세서의 날짜별 내역, 식당·종류·기록 단가별 수량 및 합계와 인쇄 버튼 (부가세 계산 및 인쇄 양식 미검증; 이름·소속·구분은 현재 정보)
- 근로자별 월간 가상 출역일에 식사 종류별 기록 일괄 추가·삭제. 추가 시 기존 기록의 단가를 보존하며 출역 취소일의 기록은 일괄 삭제하지 않음
- 현장·근로자·월별 가상 노임의 직접 입력 또는 출역 기준 시험 계산과 여섯 공제 항목 또는 별도 공제 총액의 입력 및 단순 차액 조회. 직접 입력한 총액과 항목별 합계를 구분해 보존하고 엑셀에 적용 방식을 표시합니다 (세금 자동 계산과 실제 명세서 미구현, 화면 시험 미완료).
- 가상 노임 화면과 엑셀에 조회 시점의 출역일·기록된 시험 공수·공수 미기록 일수 표시, 조회 조건을 포함한 인쇄 선택 제공 (조회한 계산액은 직접 적용해야 함, 인쇄 화면 미검증)
- 가상 노임의 이름·소속·직종은 등록 시점 값을 보존하며, 이전 기록에 당시 정보가 없으면 '기록 없음'으로 표시
- 현장별 가상 자료실 글의 분류·제목·본문과 근로자 공개 설정, 시험 첨부파일 및 같은 현장 근로자의 공개 글·첨부파일 조회. 본문은 굵게·기울임·밑줄·취소선·목록·HTTP/HTTPS 링크·표를 지원하며 기존 일반 글과 첨부를 보존합니다. 서식 있는 본문을 변경하는 API에는 `bodyRich`를 전달하고, 목록의 `version`을 함께 보내면 이전 화면의 변경을 차단합니다. 본문 이미지는 지원하지 않고 파일로 첨부합니다. 공개 중지 시 근로자의 첨부 접근을 차단하며 실제 브라우저·모바일 화면은 미검증입니다.
- 현장별 가상 사진 업로드와 촬영일·설명 수정, 기간·검색어 조회 및 삭제. 검색된 사진은 크게 보고 이전·다음으로 이동하거나 내려받을 수 있습니다. J웹 화면은 조회 이후 사진이 바뀌면 보기·다운로드·수정·삭제를 거절합니다. 기존 API 호출자가 버전을 생략하면 기존 방식대로 처리됩니다. 실제 브라우저 화면과 휴대전화는 미검증입니다.
- 가입 링크로 현장별 시험 아이디·암호를 등록하고 별도 근로자 세션으로 로그인·로그아웃

가입 초대 주소로 접속한 경우 시험 가입 또는 로그인 성공 후 서버가 반환한 현장 로그인 주소로 바꾸도록 처리합니다. 가입 화면을 열어 둔 사이 관리자가 현장 QR을 교체해도 성공 응답 당시의 주소와 홈 화면 연결 정보를 사용합니다. 이후에 다시 교체하면 받은 주소는 무효가 될 수 있습니다. 주소 변경이 차단되면 현장 로그인 링크를 표시합니다. 브라우저 주소 전환과 휴대전화 홈 화면 동작은 실제 화면에서 아직 검증하지 않았습니다.

가입 QR로 처음 연 화면에서 등록 후 로그인하지 않은 채 화면을 유지하는 동안 추가 시험 가입은 처음 사용한 초대를 확인합니다. 현장 QR을 교체해도 초대가 유효하면 새 가입이 가능하지만 초대가 중지되거나 만료되면 거절됩니다. 로그아웃하거나 주소가 바뀐 뒤 화면을 새로 열면 현장 QR의 가입 설정이 적용되므로 별도 가입 QR을 다시 열어야 할 수 있습니다. 로그아웃 후에는 같은 현장의 현재 설정을 확인한 뒤 현장 주소로 가입하며 확인에 실패하면 가입을 열지 않습니다.

시험 근로자 로그인은 5분 동안 현장·아이디별 실패 10회 또는 서버 전체 실패 100회에 도달하면 일시 제한됩니다. 가입 주소와 로그인 주소의 실패 횟수는 같은 현장 계정에 합산됩니다. 제한 기록은 서버 재시작 시 사라지며 운영용 보안 체계를 대신하지 않습니다.

시험 로그인 시각은 요청 본문을 모두 받은 시점에 확인합니다. 입력이 자정 전후로 지연되더라도 출역 날짜와 세션 만료는 처리 시점에 맞춰 기록됩니다. 근로자 자가점검과 교육 확인도 요청 본문을 받은 시점의 날짜를 사용합니다.

현장에 등록된 협력사와 직종은 해당 현장의 가입 화면에서 선택할 수 있으며 직종은 빠른 선택 버튼도 제공합니다. 등록되지 않은 소속과 직종을 직접 입력할 수도 있습니다. 직영은 소속을 생략할 수 있고, 근로를 제공하지 않는 사람은 소속과 직종을 생략할 수 있습니다. 협력업체 구분은 소속과 직종을 입력해야 합니다. 소속은 이름 문자열로 저장하므로 협력사 이름을 바꿔도 기존 출입자나 과거 출역의 소속은 자동 변경되지 않습니다. 사용 중이지 않은 협력사는 등록 목록에서 삭제할 수 있습니다.

가입 화면의 확인란은 시험 데이터 저장 안내를 확인하는 용도이며 실제 개인정보 처리 동의나 법적 약관이 아닙니다. 실제 운영에 필요한 동의 절차, 개인정보 보관 정책과 근로자 본인 인증은 구현되지 않았습니다.

## 남은 작업

인증, 현장별 권한, 다중 사용자 보안, 외부 접속, 실제 기기 QR 시험과 업무 양식·계산·첨부·인쇄·연동을 구현하고 검증해야 합니다. 작업일보는 가상 전일·당일 수량과 누계 및 표별 합계를 표시하며 자재 규격과 단위를 저장합니다. 기존 자유 입력 수량은 보존하고 미입력 수량을 0으로 추정하지 않습니다. 단위가 다른 자재의 합계는 수치 합산일 뿐입니다. 이전 일보를 불러오면 전일·당일 수량은 다시 입력해야 하며 TBM·교육 내용 불러오기도 시험 기능입니다.

관리자는 현장별 시험 결재자를 등록하고 문서 상세에서 안전 문서는 최대 4명, 업무 문서는 최대 9명을 순서대로 지정할 수 있습니다. 결재선이나 참조자 저장은 쓰기 잠금을 얻은 뒤 로그인과 문서 상태 및 대상 계정을 다시 확인합니다. 결재 요청 후 지정된 첫 계정만 시험 결재 화면에서 문서와 일반 첨부를 볼 수 있으며 승인하면 다음 계정으로 넘어갑니다. 반려하면 문서가 반려 상태가 되고, 수정 후 다시 요청하면 처음부터 진행합니다. 결재자를 지정한 문서는 관리자 개별·일괄 승인으로 우회할 수 없습니다. 계정을 중지하거나 암호를 바꾸면 기존 시험 세션은 종료됩니다. 중지된 결재자가 차례인 문서는 관리자가 요청을 취소하고 결재 순서를 다시 지정할 수 있습니다. 결재 화면에는 계획서의 연결 장비·장구·장소·점검, 위험성평가의 시험 활동, 작업허가의 사전 점검·연장과 교육 대상자의 당일 시험 확인·서명을 표시합니다. 교육 종류별 서명은 해당 문서의 참석 증명이 아닙니다. 새 결재 요청에는 별도 결재자 지정 여부와 관계없이 문서·결재 화면에 포함되는 연결 기록과 파일을 요청 시점에 데이터베이스에 복사하며, 지정된 결재자는 같은 사본을 봅니다. 다시 요청하면 별도 사본을 만들고 이전 사본은 처리 이력에서 확인할 수 있습니다. 이전 요청의 자료는 소급해 만들지 않으며 사본이 없던 별도 결재자 대기 요청은 취소 후 다시 요청해야 시험 승인할 수 있습니다. 사본 크기만큼 DB 용량이 증가합니다. 다른 유형의 별도 기록은 모두 표시되지 않습니다. 실제 결재선의 권한과 저장 규칙은 확인되지 않았으며 시험 서명은 신원이나 법적 효력을 증명하지 않습니다. 화면 시험은 미완료입니다.

시험 결재 순서 설정에서 같은 현장과 같은 유형의 이전 문서 중 결재선이 있는 가장 최근 문서의 순서를 불러올 수 있습니다. 불러온 뒤 별도로 저장해야 적용되며, 비활성 결재자가 포함된 경우 직접 다시 선택해야 합니다. 이는 J웹의 시험 규칙입니다.

출역은 시험 근로자 로그인 또는 같은 현장 QR에서 기존 세션을 복원할 때 당일 기록이 없으면 자동으로 표시되며 관리자가 수동 수정할 수 있습니다. 재접속은 기존 수동 기록을 덮어쓰지 않습니다. 출역은 서명이나 교육 참가 기록을 생성하지 않습니다. 근로자 본인 인증, 실제 출입 시각과 실제 노임 확정은 아직 구현되지 않았습니다. 기간별 합계는 출역한 근로자와 날짜를 합한 인일입니다.

기존 세션에서 QR 접속을 복원할 때 서버는 로그인된 현장과 유효한 현장 접속 주소 또는 가입 초대를 함께 확인합니다. 현장 주소를 교체하면 이전 주소를 이용한 복원은 거절되지만 기존 로그인 세션은 유지됩니다. 주소는 전달될 수 있으므로 이 검사는 실제 현장 방문이나 위치를 증명하지 않습니다. 실행 중이던 이전 화면은 갱신해야 새 복원 요청을 사용합니다.

시험 위치 확인은 기본적으로 꺼져 있으며, 관리자가 가상 기준 좌표·허용 반경·최대 위치 오차를 설정할 수 있습니다. 켜진 현장은 근로자 시험 로그인과 기존 세션의 QR 재접속 시 기기 위치 권한을 요청합니다. 서버는 저장 잠금을 얻은 뒤 현재 설정과 좌표·오차 및 측정 시각을 확인하고, 통과한 좌표·거리·시각을 로컬 DB에 기록합니다. 측정은 서버 시각 기준 2분 이내여야 하며 최대 30초의 미래 시각을 허용합니다. 관리자는 날짜별 기록을 삭제할 수 있고, 설정을 꺼도 기존 기록은 자동 삭제되지 않습니다. HTTPS와 기기 위치 권한이 필요하며, 위치는 조작될 수 있어 실제 출입 증거가 아닙니다. 실제 위치 대신 가상 자료만 사용하세요. 실제 화면은 확인하지 못했습니다.

시험 공수는 출역한 날짜에 관리자가 0부터 9.99까지 소수 둘째 자리로 수동 입력하며 빈칸은 미기록입니다. 기존 기록의 알 수 없는 공수는 미기록으로 유지합니다. 출역을 취소하면 조회에서 빠지지만 저장된 값은 보존되어 같은 날짜를 다시 출역 처리하면 나타납니다. 근로자와 관리자 집계의 합계는 입력된 값만 합산하고 미기록 일수를 따로 표시합니다. 시험 노임 계산에는 적용할 수 있지만 실제 급여 확정이나 근로시간 확인에는 사용하지 않습니다.

시험 일당은 출역한 날짜에 수동으로 입력하며 일당과 공수가 모두 있을 때만 곱한 금액을 원 단위로 반올림해 표시합니다. 빈 값과 0을 구분하고 출역 취소 시 값을 보존합니다. 이 계산은 가상 확인용이며 세금 자동 계산, 실제 노임 확정이나 지급을 지원하지 않습니다.

가상 노임 기록은 저장 당시의 이름·소속·직종·근로 구분과 직접 입력 또는 출역 기준으로 적용한 시험 금액을 보존합니다. 소속·근로 구분·이름으로 조회하면 목록과 직종별 합계, 엑셀에 같은 조건이 적용됩니다. 이전 기록에 근로 구분이 없으면 임의로 채우지 않으며 특정 구분 검색에 포함되지 않습니다. 함께 표시되는 출역일, 시험 공수와 일당 시험 계산액 합계는 조회 시점의 같은 현장·근로자·월 기록이므로 나중에 출역이 변경되면 달라질 수 있으며, 이 수치는 저장된 노임 금액을 자동으로 변경하지 않습니다. 일당 시험 계산액은 날짜별로 반올림한 금액만 합산하며 월급·연봉·기타와 값이 빠진 일수는 제외 일수로 표시합니다.

출역 기준 시험 노임은 해당 월의 일당과 공수를 날짜별로 곱해 반올림하고, 직영과 그 외로 나눈 각 그룹의 양수 월급·연봉 금액이 같으면 한 번만 사용합니다. 연봉은 월 지급액으로 환산하지 않으며 적용 전에 이를 확인합니다. 양수인 급여 종류가 같은 구분에서 혼합되거나 양수 월급·연봉 금액이 다르면 적용할 수 없습니다. 기타 양수, 미기록 또는 금액 한도 초과도 적용할 수 없습니다. 월급·연봉·기타가 있는 경우 출역 당시 근로 구분도 필요합니다. 계산 당시 출역 정보가 저장 전에 바뀌면 저장을 거절하고, 저장 후 바뀌면 금액을 유지하며 재확인이 필요하다고 표시합니다. 직접 입력한 공제는 유지합니다. 이 금액은 실제 급여나 원본 계산 규칙을 증명하지 않습니다.

API에서 출역 기준을 적용하려면 `/api/wages/estimate`에서 받은 계산액과 `version`을 노임 저장 요청의 `gross`, `grossMode: 'attendance'`, `attendanceVersion`으로 전달합니다. 계산 방식을 생략하는 이전 API 호출은 직접 입력으로 저장하며, 출역 정보가 달라졌으면 계산을 다시 조회해야 합니다.

노임 화면과 엑셀에는 조회 월의 날짜별 공수와 시험 계산액도 표시됩니다. 출역하지 않은 날짜와 출역했지만 값이 없는 날짜를 구분하며, 날짜별 값 역시 조회 시점의 시험 기록입니다.
