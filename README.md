# J웹(제이웹)

직원 내 정보는 저장 요청 중 입력을 잠그고, 저장 후 추가 변경이 감지되면 화면에 남겨 둡니다. 저장은 됐지만 재조회가 실패한 경우에는 완료 여부를 구분해 알리고 오래된 정보의 재전송을 막습니다. 최신 정보를 다시 조회하기 전에 미저장 내용을 복사해 주세요.

출역정보 전환은 전역 관리자가 같은 현장의 중복 가입 기록을 정리하는 시험 기능입니다. 출역 날짜, 기존 기록자와 대상자를 선택하면 출역·식대·공지 확인·교육 확인·자가점검의 이동 건수와 충돌을 먼저 확인하고, 대상자의 시험 서명을 입력해 실행합니다. 두 출입자가 같은 사람인지 자동으로 확인하지 않습니다. 대상에 같은 기록이 있으면 덮어쓰지 않으며 미리보기 후 자료가 바뀌면 다시 조회해야 합니다. 급여대장·보호구·다른 날짜와 문서 작성자 정보는 이동하지 않습니다.

전환 전 기록자와 당시 기록·시험 서명, 처리 관리자와 대상자 서명은 SQLite에 보존되며 전역 관리자는 같은 날짜의 전환 이력에서 확인할 수 있습니다. 같은 요청의 재전송은 중복 저장하지 않습니다. 전환은 자동으로 되돌릴 수 없고, 서명과 이력에는 개인정보가 포함될 수 있으므로 데이터와 백업에 대한 접근을 제한하세요. 실제 브라우저·휴대전화 검증은 아직 완료하지 않았습니다.

출입자 목록과 편집창은 로그아웃이나 관리자 계정 변경 뒤 늦게 도착한 조회 응답을 표시하지 않습니다. 출입자 목록의 최근 가입일 정렬은 가입 기록 시각을 기준으로 하며 가입 기록이 없는 사람은 뒤에 표시합니다. 등록 시작일·종료일 검색은 출입자 명부의 등록일을 기준으로 합니다. 별도의 출역 시작일·종료일 검색은 해당 기간에 출역 기록이 하루 이상인 사람을 찾으며, 출역 취소는 제외합니다. 최초 출역 기록은 현재 저장된 출역 중 가장 이른 날짜이며, 과거 기록의 추가·취소에 따라 달라집니다. 전역 관리자 목록과 엑셀 내보내기, 배정 현장 관리자 목록에 같은 출역 조건을 적용합니다. 가입일 정렬과 이를 적용한 목록·내보내기는 전역 관리자만 사용할 수 있습니다. 이전에 현장 제한 관리자 API에서 `order=recent`를 사용했다면 기본 정렬로 조회해야 합니다.

서류 출력 화면에서 선택한 현장의 가상 사업체명·주소·연락처·대표자와 근무장소를 저장하고 시험용 근로계약 서식에 표시할 수 있습니다. 저장된 정보가 변경되거나 관리자 세션이 바뀌면 인쇄를 중단합니다. 해당 서식은 실제 근로계약서나 공식 서식이 아닙니다. 실제 브라우저·인쇄 결과는 확인하지 않았습니다.

현장 현황은 오늘 출역한 인원을 출역 당시 저장한 구분과 직종별로 집계하고 오늘을 포함한 최근 7일의 일별 출역 인원을 표시합니다. 이전 기록에 값이 없으면 미기록으로 표시하며 현재 출입자 정보로 추정하지 않습니다. 오늘 안전 활동에는 선택한 현장의 주요 유형별 오늘 날짜 문서 유무와 임시저장·결재 대기·승인·반려 건수 및 문서 목록을 표시합니다. ‘오늘의 안전 활동 통계 보기’는 선택한 현장과 오늘 날짜를 통계 화면에 적용합니다. 기계·장비 시험 점검도 계획서에 연결된 점검일별 기록 수를 별도로 표시합니다. 점검 기록 수는 결재 또는 실제 점검 완료를 뜻하지 않습니다. 오늘 날짜 문서가 없다는 표시는 문서에 입력된 날짜를 기준으로 하며, 이전 날짜의 문서나 실제 현장 활동의 완료 여부를 판단하지 않습니다. 실제 출역 여부와 브라우저·휴대전화 화면은 검증하지 않았습니다.

기본 서류 분류 수정 화면은 조회 시점의 확인값을 함께 보내므로 다른 관리자가 이름이나 설명을 바꾼 경우 저장을 중단하고 입력을 유지합니다. 직접 API를 사용하는 이전 클라이언트는 확인값을 생략할 수 있으며 그 경우 동시 수정 보호가 적용되지 않습니다.

작업계획서의 가상 작업자 역할에는 운전원, 유도자, 신호수, 작업지휘자와 직영 운전원을 선택할 수 있습니다. 작업자별 신호 방법과 네 가지 시험 교육 구분을 여러 항목 선택하고 기타 설명을 각각 저장할 수 있습니다. 실제 교육·자격 확인은 제공하지 않습니다. 작업계획서는 등록 협력사를 선택해 식별자와 작성 당시 업체명을 함께 저장할 수 있습니다. 같은 이름의 업체는 공종과 번호로 구분하며, 목록에서는 업체 선택과 업체명 포함 검색을 함께 적용합니다. 업체 연결이 없는 이전 계획서는 업체 전체를 선택하고 이름으로 찾습니다. 다른 현장의 업체는 연결할 수 없고 이미 연결된 계획서를 이전 클라이언트로 수정할 때 식별자를 빠뜨리면 저장을 거절합니다. 업체를 직접 입력하려면 연결을 직접 입력으로 변경하세요. 업체명 변경 후 기존 계획서 이름은 보존되며 새 복사본에는 복사 시점의 등록 업체명이 기록됩니다.

근로자의 시험 작업지시에서 한 건을 저장해도 다른 지시서의 미저장 내용·서명·선택한 사진은 같은 화면에 유지합니다. 저장 중 추가로 편집한 내용이 있으면 저장된 내용과 구분해 보존하며, 서버의 지시가 바뀌거나 완료된 경우 재전송을 막고 내용을 복사하도록 안내합니다. 저장은 성공했지만 목록 갱신에 실패한 경우도 구분합니다. 이 임시 입력은 화면 새로고침이나 종료 후 복원되지 않습니다. 재사용한 행의 첨부 목록은 자동 갱신되지 않으며, 사진·다운로드 링크는 현재 쿠키의 서버 권한 검사를 따릅니다. 실제 브라우저·휴대전화 동작은 검증하지 않았습니다.

작업허가서 점검·연장의 목록은 `version`을 반환합니다. HTTP 수정·삭제에는 `expectedVersion`, 연장 서명 조회에는 같은 이름의 쿼리 값이 필요합니다. 버전 누락·변경·삭제 후 ID 재사용은 409로 거절하며 화면의 입력과 새 시험 서명을 유지합니다. 다시 조회한 뒤 내용을 확인해 수정하세요. 생성에는 버전이 필요하지 않습니다. 기존 DB의 버전은 최초 이관 때만 채우고 재시작 시 보존합니다. 내부 Store 직접 호출은 기존 승인 사본 생성과 호출자 호환을 위해 버전 생략을 허용하므로 동시 수정 보호가 필요한 호출자는 명시적으로 전달해야 합니다. 승인 후 점검·연장 변경은 가능하며 이미 저장된 승인 사본과 서명은 변경하지 않습니다.

선택 문서·현장별 일괄 미리보기는 준비 완료 및 인쇄 직전에 관리자 세션과 조회 자료를 재확인합니다. 문서·첨부 목록·서명·연결 자료, 선택한 의견·위험신고 및 보호구·출역 보고서가 달라지면 다시 조회해야 합니다. 가입 서류는 기존 가입기록·버전 검사도 적용합니다. 출력 이미지(PNG·JPEG)는 조회 바이트로 고정하고 인쇄 전 바이트 변경을 검사하며 화면 이동 시 임시 이미지 주소를 해제합니다. 마지막 검증 이후 서버에서 발생한 변경이나 브라우저 자체 인쇄 명령까지 막는 기능은 아닙니다. 비동기 확인 후 실제 브라우저 인쇄창·모바일·프린터 동작은 아직 검증하지 못했습니다.

관리자 문서 편집은 초기 목록을 불러오거나 저장할 때 계정·현장·화면 변경을 확인합니다. 저장 요청을 이미 전송한 뒤 화면이 바뀌면 서버 처리는 완료될 수 있으며, 이때 이전 응답은 현재 화면에 적용하지 않습니다. 다른 탭에서 쿠키만 변경한 경우는 감지하지 못합니다. 실제 브라우저 화면은 미검증입니다.

이전 위험성평가 내용 조회는 현장·계정·화면·조회 조건이 바뀌거나 새 조회를 시작하면 이전 응답과 선택을 무시합니다. 다른 탭에서 쿠키만 바뀐 경우는 이 화면에서 감지하지 못합니다. 실제 브라우저 화면은 미검증입니다.

위험성평가 활동의 수정·삭제·서명·첨부 변경은 조회한 `revision`과 현재 자료가 같을 때만 저장합니다. 활동과 파일을 조회하는 도중 현장·계정·화면·문서 또는 조회 세대가 바뀌면 이전 응답과 오류는 현재 화면에 적용하지 않습니다. 저장·삭제·서명·첨부를 이미 전송한 뒤 화면을 바꾸면 서버 처리는 완료될 수 있지만 이전 응답이 새 화면을 갱신하지 않습니다. 다른 탭에서 바뀐 쿠키만으로 계정 변경을 감지하지는 못합니다. 본문·참석자·첨부·서명 변경이나 삭제 후 같은 번호로 재생성된 활동에는 이전 화면의 요청을 409로 거절하며 편집창의 입력은 유지합니다. 최신 자료를 다시 열기 전에 입력을 복사해 두세요. 활동 생성은 별도 요청마다 새 활동을 만드는 기존 방식이며 자동 중복 병합은 하지 않습니다. 구형 DB는 자료를 보존하면서 버전을 부여합니다. 구형 HTTP 클라이언트는 새로 조회하여 수정·삭제·첨부 요청의 `x-risk-revision` 헤더 또는 서명 요청 본문의 `expectedRevision`을 전달해야 합니다. 버전 누락도 409입니다. 내부 Store 호출은 기존 호환을 위해 버전을 생략할 수 있으므로 동시 편집을 구현하는 호출자는 반드시 버전을 전달해야 합니다. 승인 당시 보존 사본은 이후 활동 변경과 독립적으로 유지합니다.

현장별 서류 출력의 신규 가입 서류는 J웹 가입기록 시각을 한국시간(UTC+09:00) 날짜로 바꾸어 선정합니다. 수동 출입자 등록일이나 최근 조회일 기준이 아니며, 가입기록이 없는 출입자는 포함하지 않습니다. 과거 날짜도 조회할 수 있지만 인적사항·보호구 내역·첨부는 현재 자료입니다. 전역 관리자만 조회하며 한 사람의 서류를 한 항목으로 세어 문서·보고서와 합계 20개까지 선택합니다. 기존 가입정보·시험 서명과 PNG·JPEG·WebP 이미지 및 PDF 첨부를 포함하며 그 밖의 파일 원문은 별도 확인해야 합니다. PDF는 전체 20개·10MB·30쪽까지이며 작업계획서 PDF와 같은 렌더링 제한을 적용합니다. 준비 완료와 인쇄 직전에 로그인 및 선택한 가입 서류를 재검증하고, 변경·권한 오류·이미지나 PDF 준비 실패 시 인쇄하지 않습니다. 이는 독립적인 시험 규칙이며 실제 브라우저·프린터 결과는 미검증입니다.

## 선택형 공사 중단 알림톡

알림톡은 기본 비활성입니다. 제공업체가 아직 없으면 설정하지 않아도 다른 기능을 이용할 수 있습니다. 전역 관리자는 사고 대응 안내에서 현장과 직접 입력한 국내 휴대전화 번호 1~100개를 선택하고, 템플릿 변수 입력 → 전체 본문·번호 미리보기 → 확인 체크 → 발송 순서로 요청합니다. 직원·근로자 명부를 자동 수신자로 사용하지 않습니다. 실제 신고나 관계 기관 보고를 대신하지 않습니다.

선택 가능한 연결은 네이버클라우드 SENS입니다. 운영자가 계약·채널·검수된 **일반 텍스트 템플릿**을 준비한 경우에만 서버 실행 환경에 아래 값을 설정합니다. 저장소, 화면 입력, 로그에 API 비밀키를 넣지 마세요.

| 환경변수 | 설정 내용 |
| --- | --- |
| `JWEB_NOTIFICATION_PROVIDER` | 활성화할 때만 `ncp-sens` |
| `JWEB_SENS_SERVICE_ID` | Biz Message 서비스 ID (`ncp:kkobizmsg:...`) |
| `JWEB_SENS_CHANNEL_ID` | 등록된 `@채널` ID |
| `JWEB_SENS_TEMPLATE_CODE` | 검수된 템플릿 코드 |
| `JWEB_SENS_TEMPLATE_CONTENT` | 검수된 템플릿 원문. `#{변수}`는 화면에서 값을 입력해 조합 |
| `JWEB_SENS_ACCESS_KEY` | 서버 비밀 저장소로 주입한 Access Key |
| `JWEB_SENS_SECRET_KEY` | 서버 비밀 저장소로 주입한 Secret Key |

본문은 1,000자 이내이고 설정한 템플릿과 변수로 정확히 조합돼야 합니다. 버튼·이미지·강조·아이템 템플릿은 지원하지 않습니다. 설정만으로 실제 템플릿 승인이나 업체 연결 성공을 보장하지 않으며, 제공자가 최종 규격을 검증합니다. 목적지는 `https://sens.apigw.ntruss.com`으로 고정하고 리다이렉트와 SMS 대체 발송을 사용하지 않습니다.

서버가 발급한 미리보기 키는 10분간 유효합니다. 전송 전 DB에 원자적으로 claim을 남기고 외부 요청을 1회 실행합니다. 이중 클릭·동시 요청·응답 유실·서버 재시작으로 같은 키가 재전송되지 않습니다. `202`/`A000`은 **접수**이고 개별 결과 조회의 `0000`만 **전달 확인**입니다. 시간초과·프로세스 종료·수신 확인 불명(`3005`)은 불명으로 보존합니다. 발송 중 로그인 권한이 취소되더라도 외부 작업의 결과 기록은 완료하며, 재로그인 후 이력에서 확인합니다. 자동 재전송은 없습니다.

과거와 같은 현장·수신자·본문을 미리보기 하면 기존 작업이 표시됩니다. 새 발송은 이전 작업 확인과 **중복 수신·비용 위험 동의** 후 별도의 미리보기를 만들어야 합니다. 후속 미리보기가 만들어지면 이전 미발송 미리보기에서는 발송할 수 없습니다. 불명 상태에는 실제 전달된 대상이 있을 수 있으므로 업체 콘솔부터 확인하세요. 발송 이력에는 번호 마스크·상태와 업체 식별자만 저장하고 수신번호 원문·본문·API 비밀키를 저장하지 않습니다. 동일 요청 판별에는 DB 내부 키로 만든 HMAC을 사용합니다. 최근 50개 이력을 화면에 표시하며 과거 DB 기록을 자동 삭제하지 않습니다.

공식 명세: [발송](https://api.ncloud-docs.com/docs/sens-alimtalk-send), [발송 결과](https://api.ncloud-docs.com/docs/sens-alimtalk-get), [API 서명](https://api.ncloud-docs.com/docs/common-ncpapi). 검증은 가상 번호·가상 본문과 네트워크 대역만 사용했습니다. 실제 계약·승인 템플릿·수신 단말에서의 전달, 브라우저 화면 조작은 아직 검증하지 않았습니다.

건설현장 안전관리 웹앱의 초기 시험 구현입니다. 현재는 가상 데이터로 기능을 살펴보는 단계이며 실무 운영에 사용할 수 없습니다.

### AI 상담 시험 연결

관리자 화면의 AI 상담은 기본적으로 꺼져 있습니다. 업체와 API 키가 아직 없으면 질문을 보내도 외부 요청 없이 미설정 안내를 반환합니다. 기존 관리자 로그인에만 허용하며 근로자·직원 결재자·발주처 세션은 사용할 수 없습니다.

제공업체를 정한 뒤 아래 서버 환경변수를 모두 지정하고 서버를 재시작하면 연결됩니다. 자동 기본 업체나 기본 키는 없습니다. 현재는 OpenAI 호환 `chat/completions` 요청·응답 형식만 지원하므로 업체가 해당 형식과 선택한 모델의 이미지 입력을 지원하는지 확인해야 합니다.

| 환경변수 | 값 |
| --- | --- |
| `JWEB_AI_ENABLED` | 명시적으로 `1`일 때만 활성화 |
| `JWEB_AI_ENDPOINT` | 업체의 완전한 HTTPS 응답 주소(예: 업체가 제공한 `/v1/chat/completions` 주소) |
| `JWEB_AI_MODEL` | 업체의 모델 이름 |
| `JWEB_AI_API_KEY` | 해당 업체에서 발급받은 비밀 API 키 |

로컬 가상 제공업체 시험에 한해 `localhost`, `127.0.0.1`, `::1`의 HTTP 주소도 허용합니다. 리디렉션은 따라가지 않습니다. API 키는 서버 환경변수에만 입력하고 브라우저·소스·Git에 넣지 마세요. 연결을 끄려면 `JWEB_AI_ENABLED`를 제거하거나 `0`으로 바꾸고 재시작합니다. 환경변수 파일을 자동으로 읽는 기능은 없습니다.

전송되는 내용은 이번 질문(최대 4,000자)과 선택한 사진 한 장(JPEG·PNG·WebP, 최대 5MiB), 모델 이름입니다. 파일 형식과 서명을 검사합니다. 파일명, 현장 DB, 계정 정보, 이전 대화는 전송하지 않습니다. 사진 자체의 메타데이터는 제거하지 않으므로 전송 전 사진에 포함된 개인정보를 확인해야 합니다. 업체 연결 후 전송하면 업체의 요금·보관 정책이 적용됩니다. 답변은 현장 안전 판단을 대신하지 않습니다.

질문·사진·답변 본문은 로컬 DB와 서버 로그에 기록하지 않습니다. `ai_feedback` 테이블에는 무작위 답변 ID, 관리자 로그인 세션의 SHA-256 해시, 생성 시각, 좋음/나쁨 평가만 저장합니다. 평가는 제공업체로 보내지 않으며 같은 로그인에서 받은 답변에만 기록·변경할 수 있습니다. 로그아웃하거나 세션이 만료·폐기되면 이전 답변의 평가를 바꿀 수 없습니다. 서버 재시작 뒤에도 같은 유효 세션은 이전 답변을 평가할 수 있습니다. 대화 이력 복원 기능은 없습니다. 백업에는 이 평가 테이블도 포함됩니다.

각 질문은 독립적으로 처리되며 이전 대화는 제공업체에 전송되지 않습니다. 앞선 질문의 맥락이 필요하면 이번 질문에 함께 입력하세요. 선택한 사진과 전송에 성공한 사진은 화면에서 미리보고 확대할 수 있습니다. 사진 버튼은 Enter·Space로 열고, 사진 닫기 버튼 또는 Escape로 닫으면 원래 버튼으로 초점이 돌아옵니다. 사진과 대화는 이 화면에만 유지되며 새로고침하거나 페이지를 나가면 사라집니다.

요청당 30초 제한, 로그인당 동시 요청 1개와 전체 동시 요청 4개 제한이 있습니다. 업체 오류·잘못된 응답·시간초과는 한국어 오류로 표시하며 자동 재시도하지 않습니다. 실패 시 업체의 세부 오류나 키를 브라우저에 노출하지 않습니다. `node --test test/ai-chat.test.js test/ai-chat-api.test.js`는 가상 질문과 가상 제공업체 응답만 사용하며 외부 AI를 호출하지 않습니다. 실제 업체 호환성과 요금은 아직 검증하지 않았습니다.

### 데이터 백업과 별도 복원

백업은 실행 중인 SQLite의 일관된 사본을 만들고 무결성을 검사합니다. 백업과 복원 파일에서는 관리자·근로자·직원·발주처 로그인 세션을 지우므로 사본을 사용할 때 다시 로그인해야 합니다. 복원본은 현장 접속 주소를 새로 만들고 이전 가입 초대를 중지하며 현장 가입을 닫습니다. 관리자는 복원 후 새 QR을 출력하고 필요한 경우 가입을 다시 열어야 합니다. 원래 데이터베이스와 현재 로그인·QR은 바뀌지 않습니다. 백업에는 현장 자료·첨부파일·계정 해시와 접속 정보가 포함됩니다. 아래의 일반 SQLite 백업은 암호화되지 않으므로 접근이 제한된 저장소 밖의 폴더에 보관하세요.

가상 장비 출역의 기록 당시 장비 정보와 운전원 입력값도 백업에 포함됩니다. 자동 시험은 복원된 별도 서버에서 대장을 다시 읽고 현재 장비 정보와 기록 당시 정보가 구분되는지 확인합니다.

아래 예시는 폴더를 미리 만든 뒤 PowerShell에서 실행합니다. 서버가 `JWEB_DATA_DIR`을 사용한다면 백업을 실행하는 터미널에도 같은 값을 설정하세요. 대상 파일이나 SQLite 보조 파일이 이미 있으면 덮어쓰지 않습니다. 중단되거나 검사에 실패한 사본은 사용하지 마세요.

```powershell
npm run backup -- 'C:\path\backup\jweb-backup.sqlite'
npm run restore -- 'C:\path\backup\jweb-backup.sqlite' 'C:\path\restored-data'
$env:JWEB_DATA_DIR = 'C:\path\restored-data'
$env:PORT = '4174'
$env:JWEB_ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', (Read-Host '시험 관리자 암호' -AsSecureString)).Password
npm start
```

복원 대상은 기존 `jweb.sqlite`가 없는 별도 폴더여야 합니다. 위 예시는 기존 서버와 다른 포트로 복원 서버를 시작하며 `http://127.0.0.1:4174/`에서 내용을 확인합니다. 해당 포트가 사용 중이면 다른 포트로 바꿔 주세요. 복원은 해당 시점 이후 변경을 포함하지 않으며 계정과 권한도 백업 당시 상태이므로 다시 확인해야 합니다. 사본 완성 후 같은 폴더의 임시 파일에서 대상 파일로 연결하므로 파일 연결을 지원하는 파일시스템이 필요합니다.

암호화 백업을 선택하려면 기존 폴더를 미리 만들고 PowerShell에서 다음 명령을 실행합니다. 암호는 12~1,024자이며 복원할 때 같은 암호를 다시 입력해야 합니다. 암호를 잊으면 복원할 수 없습니다. 예시 경로는 실제 폴더로 바꾸고 `JWEB_DATA_DIR`을 사용 중이면 같은 터미널에 설정하세요.

```powershell
$env:JWEB_BACKUP_PASSWORD = [System.Net.NetworkCredential]::new('', (Read-Host '백업 암호' -AsSecureString)).Password
npm run backup-encrypted -- 'C:\path\backup\jweb-backup.jwbk'
npm run restore-encrypted -- 'C:\path\backup\jweb-backup.jwbk' 'C:\path\restored-data'
Remove-Item Env:JWEB_BACKUP_PASSWORD
```

`.jwbk`는 암호에서 scrypt로 만든 키와 AES-256-GCM을 사용해 암호화하고 내용 변경을 검사합니다. 복원 전에 암호와 내용이 맞지 않으면 대상 DB를 만들지 않습니다. 암호는 환경변수로 전달되므로 같은 사용자 권한의 다른 프로그램에 노출될 수 있습니다. 작업 중 시스템 임시 폴더에 암호화되지 않은 SQLite 사본이 생성되며 정상 종료 시 삭제됩니다. 강제 종료나 컴퓨터 장애 시 남을 수 있고 삭제가 완전한 데이터 소거를 보장하지는 않습니다. 원본 DB와 복원된 DB, 일반 `.sqlite` 백업도 암호화되지 않습니다. 저장 위치와 임시 폴더의 접근 권한을 관리하세요. 자동 백업이나 운영 환경 전체의 보안을 제공하지 않습니다.

동시에 저장하는 요청이 있으면 잠금이 발생한 각 SQLite 작업은 최대 3초 기다립니다. 계속 사용 중이면 저장 실패를 알리며, 사용자가 내용을 확인한 뒤 다시 시도할 수 있습니다. 대기 중에는 같은 서버 프로세스의 다른 요청도 지연될 수 있습니다.

PowerShell에서 12자 이상의 시험 관리자 암호를 입력하고 실행한 뒤 이 컴퓨터의 브라우저에서 `http://127.0.0.1:4173/`을 엽니다. 관리자 계정이 없는 최초 실행에는 암호를 설정해야 합니다. 최초 아이디는 `admin`이며, 기존 설치도 첫 실행 때 이 암호를 DB 계정으로 이관합니다. 이후에는 이 환경변수를 생략해도 됩니다.

```powershell
$env:JWEB_ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', (Read-Host '시험 관리자 암호' -AsSecureString)).Password
npm start
```

기본 관리자는 전역 권한으로 모든 현장을 관리합니다. 현장 제한 관리자는 배정 현장만 사용할 수 있으며 현재 화면은 문서 요약·교육과 TBM의 세부 항목 및 첨부 조회·위험성평가 상세 조회·작업계획서 기본정보 조회·일반 공지 임시저장·수정, 근로자 기본정보·출역·공수, 현장 QR, 장비 출역 관리를 제공합니다. 별도 시험 직원 계정은 본인이 작성한 업무 문서와 지정된 결재·참조 문서를 볼 수 있습니다. 관리자·결재자·근로자 세션은 재시작 후에도 최초 로그인 후 최대 8시간 동안 유지됩니다. 새로 작성하거나 복사한 관리자 문서는 로그인한 관리자 계정과 작성 당시 이름을 기록합니다. 이전 문서의 관리자 작성자는 소급 확인할 수 없으며 안전한 외부 배포는 아직 지원하지 않습니다.

관리자가 만드는 월간 안전관리비 문서에도 작성 당시 관리자 이름을 저장합니다. 업무 문서 목록과 관리자 상세, 지정 결재자·참조자 상세에 작성자를 표시합니다. 결재 요청 이후 근로자·직원의 이름이 바뀌어도 새 결재 사본은 요청 당시 이름을 유지하며, 이전 사본에 이름이 없으면 미기록으로 표시합니다. 이름은 화면에 표시하는 정보이며 본인 인증이나 법적 서명을 증명하지 않습니다.

직원 로그인에서는 아이디 저장과 로그인 유지를 별도로 선택할 수 있습니다. 아이디 저장 기능은 해당 브라우저에 아이디만 보관합니다. 로그인 유지는 최대 8시간이고 선택하지 않으면 브라우저 세션 쿠키를 사용합니다.

직원 화면의 API 요청은 로그인 당시 세션에 연결됩니다. 다른 탭에서 로그인 계정이나 세션이 바뀌면 이전 화면의 요청은 거절되며 입력 내용을 복사한 뒤 새로고침해야 합니다. 직접 API를 사용하는 브라우저 클라이언트는 로그인 응답 또는 세션 조회의 `context`를 `X-Reviewer-Context` 헤더로 보내야 합니다. 이전 서버 간 호출과의 호환을 위해 브라우저 출처 헤더가 없는 기존 요청은 계속 허용합니다. 이미지와 내려받기 링크의 직접 GET 요청에는 이 화면별 헤더가 붙지 않고 당시 브라우저 쿠키의 권한이 적용됩니다.

제한 관리자 문서 목록은 종류·작성일 시작/종료·제목과 내용 검색을 제공합니다. 상세에서 목록으로 돌아오면 같은 현장·계정의 검색 조건을 유지하며, 현장이나 계정을 변경하면 초기화합니다. 잘못된 날짜와 조회 실패 때 입력을 보존하며 검색 초기화도 지원합니다. 기존 문서 조회 API를 사용하고 조회 권한은 늘리지 않습니다.

제한 관리자 교육·TBM 상세는 저장된 시간·강사·장소·방법·교재 또는 날씨·작업·위험요인을 표시하며, 이전 시간과 교육방법도 그대로 읽습니다. 첨부 다운로드는 문서와 파일의 소속 일치를 검사합니다. 서명·결재·수정 기능을 새로 허용하지 않으며 기존 교육 대상 설정은 유지합니다. 현장·계정 전환 후 늦게 도착한 응답은 표시하지 않습니다. 가상 DOM 및 임시 DB HTTP 시험으로 검증하며 실제 브라우저와 모바일은 미검증입니다.

제한 관리자 위험성평가 상세는 전역 화면과 같은 표시 함수를 사용해 평가 종류·척도·기간, 공정·협력사별 위험요인과 조치, 현재·개선 후 시험 점수, 예정일·완료일·담당자·검토 의견을 읽습니다. 저장된 근골격계 항목 중 평가에 선택한 항목을 표시하고 미선택 항목은 개수로 안내합니다. 구형 단일 항목 기록도 읽습니다. 같은 현장의 위험성평가 활동 네 종류와 현재 첨부를 읽기 전용으로 조회하며, 첨부 내려받기는 조회한 활동 버전을 재검사합니다. 현재 결재 회차의 요청 당시 평가·활동·첨부와 주간 점검 시험 서명도 읽기 전용으로 확인할 수 있습니다. 결재 회차가 바뀌면 이전 화면의 파일 요청은 거절합니다. 결재 처리와 편집은 이 화면에서 제공하지 않습니다. 현장·계정·페이지·문서 전환 후 늦은 응답 차단과 특수문자 처리를 가상 DOM 시험으로 검증했습니다. 실제 브라우저·모바일 표시는 미검증입니다.

제한 관리자는 배정 현장의 작업계획서 기본정보, 중량물별 양중 방식·중량·시험 안전성 검토와 해당 문서의 첨부파일을 조회할 수 있습니다. 계획서 첨부 경로에서는 해당 현장과 문서에 속한 파일만 조회할 수 있으며 첨부 변경은 허용하지 않습니다. 기존 공통 첨부 경로는 배정 현장의 파일을 별도로 허용합니다.

휴대전화 QR 시험을 위한 HTTPS 중계 주소는 `JWEB_PUBLIC_ORIGIN`에 경로 없이 설정할 수 있습니다. 예: `https://example.test:8443`. 이 경우 서버는 계속 `127.0.0.1`에서만 수신하며 지정된 호스트와 HTTPS 출처만 허용하고 QR에 지정된 주소를 넣으며 세션 쿠키에 Secure를 추가합니다. 주소 설정만으로 중계, 인증서 또는 방화벽이 만들어지지는 않습니다. 인증·권한·운영 보안이 미완성이므로 가상 자료만 사용하고 외부 공개나 실사용에 이용하지 마세요.

내장 시험 중계는 별도의 터미널에서 `npm run proxy`로 실행합니다. 서버와 중계에 같은 `JWEB_PUBLIC_ORIGIN`, `PORT`, `JWEB_PROXY_SECRET`을 설정하고, 중계에는 `JWEB_TLS_CERT`와 `JWEB_TLS_KEY`에 인증서와 개인키 파일 경로를 지정합니다. 중계는 기본적으로 이 컴퓨터에서만 수신합니다. 휴대전화 시험 시 `JWEB_PROXY_BIND`에 이 컴퓨터의 접근 가능한 IP 주소를 지정해야 합니다. 중계 포트는 HTTPS 주소에 지정하며 서버 포트와 달라야 합니다. 중계는 시작할 때 인증서의 대체 이름이 접속 주소와 맞는지, 유효 기간과 개인키가 맞는지 확인합니다. 이 검사는 휴대전화의 인증서 신뢰를 보장하지 않습니다. 주소의 이름이 휴대전화에서 해당 IP로 연결되고 인증서가 휴대전화에서 신뢰되어야 합니다. 네트워크와 방화벽도 해당 연결을 허용해야 합니다.

인증서와 개인키는 직접 준비하고 저장소 밖에 보관하세요. 이 중계는 접속 URL을 기록하지 않지만, 다른 중계나 서버를 사용할 때도 가입 토큰이 포함된 전체 URL을 접근 기록에 남기지 않도록 설정해야 합니다. 서버와 중계를 시작한 뒤에는 HTTPS 주소로 관리자 화면을 열어 시험 QR을 만듭니다.

예를 들어, 다음 예시의 주소·IP·파일 경로를 실제 준비한 값으로 바꾼 뒤 PowerShell 두 개에서 각각 실행합니다. 두 터미널의 주소와 중계 공유 비밀은 같아야 합니다. 기존 HTTPS 설치도 이제 공유 비밀 설정이 필요하며, 누락하면 중계가 시작되지 않습니다. 공유 비밀은 충분히 무작위인 영문·숫자·밑줄·하이픈 32~256자로 준비하고 소스나 로그에 기록하지 마세요.

```powershell
# 첫 번째 터미널: 시험 서버
$env:JWEB_PUBLIC_ORIGIN = 'https://example.test:8443'
$env:JWEB_PROXY_SECRET = [System.Net.NetworkCredential]::new('', (Read-Host '두 터미널에 같은 중계 공유 비밀 입력' -AsSecureString)).Password
$env:JWEB_ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', (Read-Host '시험 관리자 암호' -AsSecureString)).Password
npm start
```

```powershell
# 두 번째 터미널: HTTPS 시험 중계
$env:JWEB_PUBLIC_ORIGIN = 'https://example.test:8443'
$env:JWEB_PROXY_SECRET = [System.Net.NetworkCredential]::new('', (Read-Host '두 터미널에 같은 중계 공유 비밀 입력' -AsSecureString)).Password
$env:JWEB_PROXY_BIND = '192.168.1.10'
$env:JWEB_TLS_CERT = 'C:\path\certificate.pem'
$env:JWEB_TLS_KEY = 'C:\path\private-key.pem'
npm run proxy
```

서버가 생성하는 현장 및 가입 QR 이미지는 512×512 픽셀이며 네 칸의 흰색 여백을 포함합니다. 자동 시험은 OpenSSL을 사용할 수 있을 때 임시 인증서로 이 컴퓨터의 로컬 주소와 사용 가능한 네트워크 IP에 HTTPS 중계를 만들고 가상 가입 QR의 판독, 가입 및 로그인 API를 확인합니다. OpenSSL이나 사용할 IP가 없으면 해당 시험은 건너뜁니다. 이 시험은 실제 휴대전화나 운영용 인증서를 검증하지 않습니다.

별도의 가상 HTTP 통합 시험은 가입 QR 판독, 가입, 로그인, 자가점검 저장과 서버 재시작 후 관리자 조회를 순서대로 확인합니다. 이름과 생년 정보만으로 가입·로그인한 계정도 점검을 저장하고 재시작 후 다시 로그인하는지 확인합니다. 실제 카메라와 휴대전화 화면은 검증하지 않습니다.

## 현재 가능한 시험

- 현장 추가 및 현장별 출입자 등록·수정, 구분·소속·직종·등록 기간과 가상 생년월일·전화번호·메모 검색, 검색 결과 엑셀 내려받기. 선택한 출입자 최대 20명의 가상 가입 정보·보호구 기록·시험 서명과 이미지·PDF 첨부서류를 미리보거나 인쇄할 수 있습니다. 다른 형식은 파일 이름만 표시합니다. 조회 후 이름·구분·소속·직종·메모가 바뀌면 다시 선택해야 하며, 준비 및 인쇄 직전에 가입·보호구·첨부 변경과 관리자 세션을 확인합니다. PDF에는 위 일괄 출력 제한을 적용합니다. 실제 개인정보, 브라우저 및 인쇄는 미검증입니다.
- 관리자는 출입자별 가상 면허 이름과 번호를 최대 20행까지 추가·수정·삭제할 수 있습니다. 각 항목은 선택 사항이고 100자 이내이며, 두 칸 모두 빈 행은 저장하지 않습니다. 이전 버전의 수정 요청이 면허 항목을 보내지 않으면 기존 값을 보존하고, 변경된 출입자는 화면을 다시 조회해야 합니다. 면허 번호는 본인 확인이나 실제 자격 검증을 제공하지 않습니다.
- 출입자의 등록 방식을 자기 등록과 일반등록으로 표시합니다. 가상 가입은 자기 등록, 관리자가 추가한 출입자는 일반등록으로 기록합니다. 관리자가 자기 등록 정보를 저장하거나 별도 전환 버튼을 누르면 일반등록으로 변경하며, 가상 계정·가입 기록·출역·첨부·세션은 유지합니다. 이전 데이터는 가입 기록과 같은 현장의 계정이 함께 있는 경우에만 자기 등록으로 이관하며 나머지는 일반등록으로 표시합니다. 이전 상태를 확인할 수 없는 기록은 실제 등록 경위와 다를 수 있습니다. 화면의 확인값이 오래되면 다시 조회해야 합니다.
- 현장별 협력사 회사명·공종 등록 및 수정 (시험용 독립 목록)
- 등록 목록에서 미사용 협력사를 삭제할 수 있습니다. 같은 현장의 출입자 소속 이름이나 문서의 협력사 이름·번호로 사용 중이면 삭제하지 않습니다. 이름·공종을 다시 확인하고 잠금을 얻은 뒤 사용 여부와 관리자 세션을 검사합니다. 삭제는 등록 목록과 가입 후보에서 숨기는 방식이며 기존 번호는 재사용하지 않습니다. 이는 독립적인 시험 규칙으로 실제 화면은 미검증입니다.
- 로컬 시험용 단일 관리자 로그인
- 가상 출입자의 날짜별·월별 출역 등록·취소와 현장별 인원 집계, 근로자·직종·소속별 기간 합계 및 날짜별 소속·직종·가상 이름·생년월일·전화번호 검색. 출역한 날짜에는 저장 당시 구분·소속·직종을 표시하고 누락된 과거 값은 미기록으로 남깁니다. 가상 생년월일은 가입 기록이 있을 때 일별·월별 표에 표시합니다.
- 관리자의 일별 출역·공수·급여 변경은 저장 잠금을 얻은 뒤 세션을 다시 확인하며, 대기 중 세션이 만료되면 저장하지 않습니다.

가입을 전송한 뒤 화면을 바꾸거나 입력·서명을 수정하면 늦은 응답이 새 입력을 지우지 않습니다. 등록이 완료되면 전송 후 변경한 값은 저장되지 않았음을 알려줍니다. 통신 오류나 서버 오류로 결과를 확인할 수 없을 때는 자동 재전송하지 않고 전송 당시 아이디로 로그인을 확인하도록 안내합니다. 요청을 보낸 뒤 창을 닫아도 서버에서 가입을 완료할 수 있으며, 등록 전 입력은 새로고침 후 복원되지 않습니다.

가입 화면에서 이용·시험 정보 저장·선택적 위치 확인 안내를 각각 펼쳐 읽고 전체 확인 후 입력 단계로 이동합니다. 이 확인은 실제 개인정보 처리 동의나 본인 확인을 제공하지 않습니다.

현장 접속 화면에서 직원 시험 계정 로그인 화면으로 이동할 수 있습니다. 직원 시험 계정은 스캔한 현장이 아니라 그 계정에 지정된 현장으로 로그인합니다. 근로자는 아이디 또는 이름과 생년월일 여섯 자리의 기기 저장을 각각 선택하고 직접 지울 수 있습니다. 선택한 정보와 현장 주소의 해시가 브라우저에 저장되며 암호나 원래 현장 주소는 저장하지 않습니다. 한 브라우저에 방식별로 최근 선택한 정보 한 건씩 저장되며 현장 QR을 교체하면 기존 정보가 자동 입력되지 않습니다. 공용 기기에서는 저장을 선택하지 마세요. 실제 휴대전화와 브라우저 화면은 검증하지 않았습니다.

같은 시험 데이터베이스를 사용하는 서버 사이에서도 근로자의 로그아웃과 암호 변경이 다른 요청에 반영되는지 확인합니다. 이는 애플리케이션의 다중 서버 운영 전체를 지원한다는 뜻은 아닙니다.

현장 QR 창은 기존 현장 접속 주소를 먼저 보여 주며, 창을 여는 것만으로 별도 가입 초대가 생기지는 않습니다. 관리자가 현장 QR 가입을 열거나 별도 가입 QR을 발급해야 신규 가입할 수 있습니다. 별도 가입 QR을 다시 발급해도 이전 QR은 만료되거나 모두 중지할 때까지 유효합니다.

현장 가입 열기와 모든 가입 QR 중지는 데이터베이스 잠금을 얻은 뒤 관리자 세션을 다시 확인합니다. 확인에 실패하면 가입 설정과 초대 변경을 저장하지 않습니다.

관리자의 결재자 계정 등록·수정, 근로자 권한·암호 변경, 현장 휴일·작업 종료 설정도 저장 잠금 후 관리자 세션을 다시 확인합니다. 근로자 암호 재설정과 기존 세션 종료는 함께 저장됩니다.

현장 QR과 별도 가입 QR은 각각 인쇄 버튼을 선택하며, 인쇄할 이미지가 아직 준비되지 않았거나 불러오지 못하면 다시 시도하도록 안내합니다. 선택한 QR과 현장명·주소만 출력하도록 설정했으나 실제 브라우저 인쇄와 종이 출력은 검증하지 않았습니다.

가입 정보 저장 전 같은 데이터베이스에서 초대와 현장 가입 상태를 다시 확인합니다. 그때 초대가 중지·만료되었거나 현장 가입이 닫혀 있거나 접속 주소가 교체되었다면 진행 중인 가입도 거절하며, 이미 저장된 가입 기록은 유지됩니다.

근로자 아이디 로그인은 암호를 확인하고, 이름·생년월일 로그인은 암호 없이 동작합니다. 두 방식 모두 세션과 자동 출역을 저장할 때 계정 상태와 접속 주소를 다시 확인합니다. 아이디 로그인 중 암호가 재설정되거나, 로그인 중 사용한 초대가 중지되면 진행 중인 로그인은 거절됩니다. 암호 재설정만으로 이름·생년월일 로그인을 막을 수는 없습니다. 별도의 유효한 현장 로그인 주소는 초대 중지 후에도 사용할 수 있습니다. 세션 저장이 실패하면 그 로그인에서 생성한 출역도 저장되지 않습니다.

QR 생성 중 다른 요청으로 현장 주소가 교체되거나 가입 초대가 중지되면 해당 QR은 반환하지 않고 다시 시도하도록 안내합니다. 같은 QR 창에서는 한 요청이 끝난 뒤 다음 요청을 시작합니다. QR을 받은 뒤 다른 관리자가 주소를 교체하거나 초대를 중지하면 이미 받은 QR도 무효가 될 수 있습니다.

새 현장의 첫 QR은 이미지 생성과 관리자 권한 확인이 성공한 뒤 접속 주소를 저장합니다. 별도 가입 QR은 접속 주소 저장과 초대 활성화를 함께 처리합니다. 다른 요청이 먼저 주소를 만들면 이전 요청은 다시 시도해야 합니다.

현장 로그인 화면은 홈 화면 추가를 위한 연결 정보와 PNG 아이콘을 제공합니다. 연결 정보의 시작 주소는 가입 초대 토큰이 없는 현장 로그인 주소입니다. 일부 기기에서는 현재 페이지 주소가 저장될 수 있으므로 가입 또는 로그인 후 주소가 현장 로그인 주소로 바뀐 것을 확인하고 홈 화면에 추가하세요. 현장 로그인 주소를 교체하면 이전 바로가기는 더 이상 사용할 수 없습니다. 실제 휴대전화의 추가·실행 동작은 검증되지 않았으며, 인터넷 연결이 필요합니다.

가입 초대 주소로 접속한 경우 시험 가입 또는 로그인 성공 후 서버가 반환한 현장 로그인 주소로 바꾸도록 처리합니다. 가입 화면을 열어 둔 사이 관리자가 현장 QR을 교체해도 성공 응답 당시의 주소와 홈 화면 연결 정보를 사용합니다. 이후에 다시 교체하면 받은 주소는 무효가 될 수 있습니다. 주소 변경이 차단되면 현장 로그인 링크를 표시합니다. 브라우저 주소 전환과 휴대전화 홈 화면 동작은 실제 화면에서 아직 검증하지 않았습니다.

관리자는 계정과 가입 기록이 없는 기존 출입자에게 개인 가입 QR을 발급할 수 있습니다. 이 주소는 24시간 동안 한 번만 사용하며, 가입할 때 관리자가 등록한 이름을 확인합니다. 가입이 완료되면 새 출입자를 만들지 않고 기존 출역·첨부와 등록 정보를 보존합니다. 출입자 정보를 수정하거나 개인 QR을 다시 발급하면 이전 개인 주소는 중지되며, 모든 가입 QR 중지와 복원 시에도 중지됩니다. 관리자가 해당 출입자에게 직접 전달해야 하고 자동 발송은 없습니다. 이 주소와 이름만으로 실제 본인을 확인하지는 못하므로 가상 자료로 시험하세요. 가상 QR 판독·HTTP·동시 가입·화면 대역 시험은 `node --test test/worker-invitation.test.js test/worker-invitation-ui.test.js test/worker-invitation-api.test.js`로 실행합니다. 실제 휴대전화와 화면은 검증하지 않았습니다.

가입 QR로 처음 연 화면에서 등록 후 로그인하지 않은 채 화면을 유지하는 동안 추가 시험 가입은 처음 사용한 초대를 확인합니다. 현장 QR을 교체해도 초대가 유효하면 새 가입이 가능하지만 초대가 중지되거나 만료되면 거절됩니다. 로그아웃하거나 주소가 바뀐 뒤 화면을 새로 열면 현장 QR의 가입 설정이 적용되므로 별도 가입 QR을 다시 열어야 할 수 있습니다. 로그아웃 후에는 같은 현장의 현재 설정을 확인한 뒤 현장 주소로 가입하며 확인에 실패하면 가입을 열지 않습니다.

시험 근로자 로그인은 최근 5분 동안 현장·아이디별 실패 10회 또는 네트워크 발신자별 실패 100회에 도달하면 해당 계정 또는 발신자만 일시 제한됩니다. 가입 주소·로그인 주소·이름과 생년월일 로그인은 같은 현장 계정에 실패 횟수를 합산합니다. 이름과 생년월일은 암호가 아니므로 이 제한만으로 본인 확인이나 개인정보 보호를 보장하지 못합니다. 발신자 제한은 현장과 아이디를 바꿔도 합산되고 로그인 성공으로 초기화되지 않습니다. 정상 로그인과 관리자 암호 초기화는 해당 계정 제한만 초기화합니다.

기본 발신자는 실제 TCP 연결 주소이며 임의의 X-Forwarded-For는 신뢰하지 않습니다. 내장 HTTPS 중계는 외부의 전용 주소·비밀 헤더를 덮어쓰며, 서버는 로컬 연결·공유 비밀 일치·유효 IP를 모두 확인한 경우에만 전달 주소를 사용합니다. 내장 중계 헤더가 있는 로컬 요청에서 서버의 공유 비밀이 누락되거나 중계와 다르면 로그인은 503 설정 오류로 거절됩니다. 다른 리버스 프록시에서 안전한 전달을 구성하지 않으면 같은 프록시 peer를 공유하는 사용자는 발신자 제한도 공유합니다. NAT처럼 실제 공인 IP가 같은 사용자도 제한을 공유합니다.

실패 기록은 요청마다 5분 만료분을 제거하며 발신자/계정 각각 최대 10,000개 키와 키별 최대 100/10개 시각만 보관합니다. 포화되면 가장 먼저 등록된 키를 제거하므로 10,000개 이상의 발신자나 계정을 동원하는 분산 공격은 오래된 제한을 소실시킬 수 있습니다. 전역 로그인 차단으로 되돌아가지 않기 위한 메모리 상한이며, 대규모 운영에는 외부 공유 제한기가 필요합니다. 제한 기록은 서버 재시작 시 사라지고 다중 서버에서 공유하지 않으며 운영용 보안 체계를 대신하지 않습니다.

시험 로그인 시각은 요청 본문을 모두 받은 시점에 확인합니다. 입력이 자정 전후로 지연되더라도 출역 날짜와 세션 만료는 처리 시점에 맞춰 기록됩니다. 근로자 자가점검과 교육 확인도 요청 본문을 받은 시점의 날짜를 사용합니다.

현장에 등록된 협력사와 직종은 해당 현장의 가입 화면에서 선택할 수 있으며 직종은 빠른 선택 버튼도 제공합니다. 직종 선택에는 현장별 후보가 없어도 공통 직종이 표시되고, 현장에 등록한 후보가 먼저 표시됩니다. 빠른 선택은 등록된 현장 직종을 표시하고, 현장 직종이 없으면 공통 직종을 표시합니다. 등록되지 않은 소속과 직종을 직접 입력할 수도 있습니다. 직영은 소속을 생략할 수 있고, 근로를 제공하지 않는 사람은 소속과 직종을 생략할 수 있습니다. 협력업체 구분은 소속과 직종을 입력해야 합니다. 소속 이름을 저장하며 등록 협력사를 선택하면 식별자도 함께 저장합니다. 협력사 이름을 바꿔도 기존 출입자나 과거 출역의 소속은 자동 변경되지 않습니다. 사용 중이지 않은 협력사는 등록 목록에서 삭제할 수 있습니다.

가입 화면의 확인란은 시험 데이터 저장 안내를 확인하는 용도이며 실제 개인정보 처리 동의나 법적 약관이 아닙니다. 실제 운영에 필요한 동의 절차, 개인정보 보관 정책과 근로자 본인 인증은 구현되지 않았습니다.

## 남은 작업

인증, 현장별 권한, 다중 사용자 보안, 외부 접속, 실제 기기 QR 시험과 업무 양식·계산·첨부·인쇄·연동을 구현하고 검증해야 합니다. 작업일보는 가상 전일·당일 수량과 누계 및 표별 합계를 표시하며 자재 규격과 단위를 저장합니다. 기존 자유 입력 수량은 보존하고 미입력 수량을 0으로 추정하지 않습니다. 단위가 다른 자재의 합계는 수치 합산일 뿐입니다. 이전 일보를 불러오면 전일·당일 수량은 다시 입력해야 하며 TBM·교육 내용 불러오기도 시험 기능입니다.

관리자는 현장별 시험 결재자를 등록하고 문서 상세에서 일반 안전 문서는 최대 4명, 업무 문서는 최대 9명을 순서대로 지정할 수 있습니다. 작업허가서의 역할별 결재는 최대 6명입니다. 결재선이나 참조자 저장은 쓰기 잠금을 얻은 뒤 로그인과 문서 상태 및 대상 계정을 다시 확인합니다. 결재 요청 후 지정된 첫 계정만 시험 결재 화면에서 문서와 일반 첨부를 볼 수 있으며 승인하면 다음 계정으로 넘어갑니다. 반려하면 문서가 반려 상태가 되고, 수정 후 다시 요청하면 처음부터 진행합니다. 결재자를 지정한 문서는 관리자 개별·일괄 승인으로 우회할 수 없습니다. 계정을 중지하거나 암호를 바꾸면 기존 시험 세션은 종료됩니다. 중지된 결재자가 차례인 문서는 관리자가 요청을 취소하고 결재 순서를 다시 지정할 수 있습니다. 결재 화면에는 계획서의 연결 장비·장구·장소·점검, 위험성평가의 시험 활동, 작업허가의 사전 점검·연장과 교육 대상자의 당일 시험 확인·서명을 표시합니다. 교육 종류별 서명은 해당 문서의 참석 증명이 아닙니다. 새 결재 요청에는 별도 결재자 지정 여부와 관계없이 문서·결재 화면에 포함되는 연결 기록과 파일을 요청 시점에 데이터베이스에 복사하며, 지정된 결재자는 같은 사본을 봅니다. 다시 요청하면 별도 사본을 만들고 이전 사본은 처리 이력에서 확인할 수 있습니다. 이전 요청의 자료는 소급해 만들지 않으며 사본이 없던 별도 결재자 대기 요청은 취소 후 다시 요청해야 시험 승인할 수 있습니다. 사본 크기만큼 DB 용량이 증가합니다. 다른 유형의 별도 기록은 모두 표시되지 않습니다. 실제 결재선의 권한과 저장 규칙은 확인되지 않았으며 시험 서명은 신원이나 법적 효력을 증명하지 않습니다. 화면 시험은 미완료입니다.

시험 결재 순서 설정에서 같은 현장과 같은 유형의 이전 문서 중 결재선이 있는 가장 최근 문서의 순서를 불러올 수 있습니다. 불러온 뒤 별도로 저장해야 적용되며, 비활성 결재자가 포함된 경우 직접 다시 선택해야 합니다. 이는 J웹의 시험 규칙입니다.

출역은 시험 근로자 로그인 또는 같은 현장 QR에서 기존 세션을 복원할 때 당일 기록이 없으면 자동으로 표시되며 관리자가 수동 수정할 수 있습니다. 재접속은 기존 수동 기록을 덮어쓰지 않습니다. 출역은 서명이나 교육 참가 기록을 생성하지 않습니다. 근로자 본인 인증, 실제 출입 시각과 실제 노임 확정은 아직 구현되지 않았습니다. 기간별 합계는 출역한 근로자와 날짜를 합한 인일입니다.

기존 세션에서 QR 접속을 복원할 때 서버는 로그인된 현장과 유효한 현장 접속 주소 또는 가입 초대를 함께 확인합니다. 현장 주소를 교체하면 이전 주소를 이용한 복원은 거절되지만 기존 로그인 세션은 유지됩니다. 주소는 전달될 수 있으므로 이 검사는 실제 현장 방문이나 위치를 증명하지 않습니다. 실행 중이던 이전 화면은 갱신해야 새 복원 요청을 사용합니다.

시험 위치 확인은 기본적으로 꺼져 있으며, 관리자가 가상 기준 좌표·허용 반경·최대 위치 오차를 설정할 수 있습니다. 켜진 현장은 근로자 시험 로그인, 기존 세션의 QR 재접속과 시험 퇴근 시 기기 위치 권한을 요청합니다. 서버는 저장 잠금을 얻은 뒤 현재 설정과 좌표·오차 및 측정 시각을 확인하고, 통과한 좌표·거리·시각을 로컬 DB에 기록합니다. 측정은 서버 시각 기준 2분 이내여야 하며 최대 30초의 미래 시각을 허용합니다. 관리자는 날짜별 기록을 삭제할 수 있고, 설정을 꺼도 기존 기록은 자동 삭제되지 않습니다. HTTPS와 기기 위치 권한이 필요하며, 위치는 조작될 수 있어 실제 출입 증거가 아닙니다. 실제 위치 대신 가상 자료만 사용하세요. 실제 화면은 확인하지 못했습니다.

시험 공수는 출역한 날짜에 관리자가 0부터 9.99까지 소수 둘째 자리로 수동 입력하며 빈칸은 미기록입니다. 기존 기록의 알 수 없는 공수는 미기록으로 유지합니다. 출역을 취소하면 조회에서 빠지지만 저장된 값은 보존되어 같은 날짜를 다시 출역 처리하면 나타납니다. 근로자와 관리자 집계의 합계는 입력된 값만 합산하고 미기록 일수를 따로 표시합니다. 시험 노임 계산에는 적용할 수 있지만 실제 급여 확정이나 근로시간 확인에는 사용하지 않습니다.

시험 일당은 출역한 날짜에 수동으로 입력하며 일당과 공수가 모두 있을 때만 곱한 금액을 원 단위로 반올림해 표시합니다. 빈 값과 0을 구분하고 출역 취소 시 값을 보존합니다. 이 계산은 가상 확인용이며 세금 자동 계산, 실제 노임 확정이나 지급을 지원하지 않습니다.

가상 노임 기록은 저장 당시의 이름·소속·직종·근로 구분과 직접 입력 또는 출역 기준으로 적용한 시험 금액을 보존합니다. 소속·근로 구분·이름·가상 생년월일·전화번호 검색은 목록과 직종별 합계, 엑셀에 같은 조건이 적용됩니다. 생년월일은 노임에 보존된 값이고 전화번호 검색은 현재 연락처를 사용하며, 전화번호 자체는 검색 결과에 추가하지 않으며 인쇄 안내에는 검색어 대신 적용 여부만 표시합니다. 이전 기록에 근로 구분이나 생년월일이 없으면 임의로 채우지 않습니다. 함께 표시되는 출역일, 시험 공수와 일당 시험 계산액 합계는 조회 시점의 같은 현장·근로자·월 기록이므로 나중에 출역이 변경되면 달라질 수 있으며, 이 수치는 저장된 노임 금액을 자동으로 변경하지 않습니다. 일당 시험 계산액은 날짜별로 반올림한 금액만 합산하며 월급·연봉·기타와 값이 빠진 일수는 제외 일수로 표시합니다.

출역 기준 시험 노임은 해당 월의 일당과 공수를 날짜별로 곱해 반올림하고, 직영과 그 외로 나눈 각 그룹의 양수 월급·연봉 금액이 같으면 한 번만 사용합니다. 연봉은 월 지급액으로 환산하지 않으며 적용 전에 이를 확인합니다. 양수인 급여 종류가 같은 구분에서 혼합되거나 양수 월급·연봉 금액이 다르면 적용할 수 없습니다. 기타 양수, 미기록 또는 금액 한도 초과도 적용할 수 없습니다. 월급·연봉·기타가 있는 경우 출역 당시 근로 구분도 필요합니다. 계산 당시 출역 정보가 저장 전에 바뀌면 저장을 거절하고, 저장 후 바뀌면 금액을 유지하며 재확인이 필요하다고 표시합니다. 직접 입력한 공제는 유지합니다. 이 금액은 실제 급여를 증명하지 않습니다.

API에서 출역 기준을 적용하려면 `/api/wages/estimate`에서 받은 계산액과 `version`을 노임 저장 요청의 `gross`, `grossMode: 'attendance'`, `attendanceVersion`으로 전달합니다. 계산 방식을 생략하는 이전 API 호출은 직접 입력으로 저장하며, 출역 정보가 달라졌으면 계산을 다시 조회해야 합니다.

노임 화면과 엑셀에는 조회 월의 날짜별 공수와 시험 계산액도 표시됩니다. 출역하지 않은 날짜와 출역했지만 값이 없는 날짜를 구분하며, 날짜별 값 역시 조회 시점의 시험 기록입니다.

노임 화면의 직종별 가상 내역은 같은 검색 조건의 근로자별 시험 공수·미기록 일수·저장된 노임·가상 생년월일·비고와 직종 합계를 표시합니다. 신규 노임 기록에 가입 시 입력된 가상 생년월일을 보존하고 이전 노임에 없는 값은 미기록으로 둡니다. 비고는 노임 입력과 수정에서 관리하며 두 항목은 가상 엑셀에도 포함됩니다. 공수가 모두 미기록인 직종은 합계도 미기록으로 표시하며 실제 지급 명세서가 아닙니다.

시험 교육 참가 확인에는 안전이 확보되지 않은 작업에 관한 권리·의무 확인이 포함됩니다. 이전 참가 기록에는 이 확인 정보가 없으며 새 기록 역시 실제 교육이나 본인 확인의 증거가 아닙니다.

새로 등록한 출역은 당시 소속·직종을 보존합니다. 이전 버전에서 만든 출역에는 당시 소속·직종 정보가 없어 해당 기준으로 집계할 때 `기록 없음`으로 표시합니다. 근로자별 집계의 이름·소속 표시는 현재 출입자 정보를 사용합니다.

출역 관리의 월별 표에서 근로자별 미리보기·인쇄를 열 수 있습니다. 선택한 현장과 월의 출역자를 구분·직종·소속·이름으로 조회하며 인쇄 직전 자료와 필터 변경을 확인합니다. 실제 브라우저와 종이 출력은 미검증입니다.

월별 출역 정보 확인·변경에서 날짜별로 저장된 구분·소속·직종·시험 일당을 확인할 수 있습니다. 해당 월의 다음 달 5일을 참고 날짜로 표시하지만 J웹은 기한 이후의 시험 변경도 허용합니다. 변경하면 선택한 근로자의 해당 월 출역 기록에 입력한 항목을 덮어쓰고 기간별 집계에도 반영됩니다. 저장 잠금을 얻은 뒤 관리자 세션과 조회한 월별 기록을 다시 확인하며, 이전 API 요청이 확인값을 생략하면 기록 충돌 검사는 하지 않습니다. 시험 일당을 0으로 입력하면 0을 기록하고 빈칸은 기존 값을 유지합니다. 변경 이력은 보관하지 않습니다. 취소된 출역, 출입자 기본 정보와 저장한 노임은 바꾸지 않습니다. 가상 자료용 기능이며 실제 급여 산정에 사용하지 않습니다.

출입자 등록일은 서버의 현지 날짜를 사용합니다. 이전 버전에서 만든 출입자는 등록일을 알 수 없어 비워 두며, 등록 기간으로 검색하면 그 기록은 결과에 포함되지 않습니다.

위험요인 기록과 숫자 점수는 시험용이며 등급 경계와 이행 추적은 완성되지 않았습니다. 숫자 점수는 가능성과 중대성을 곱하며, 기존 기록에 저장된 두 값이 있으면 다시 계산해 표시합니다. 실제 안전관리 판단에 사용하지 마세요.

평가 척도를 바꾸려면 새 척도에 맞지 않는 기존 위험 등급·가능성·중대성 선택을 먼저 비워야 합니다. 선택값은 자동으로 삭제되지 않습니다.

### 문서 편집 충돌

관리자와 근로자의 문서 조회 응답에는 정수 `edit_version`이 포함됩니다. 기존 문서를 PUT으로 수정할 때는 편집을 시작하며 받은 값을 `expectedEditVersion`으로 보내야 합니다. 누락·잘못된 값·다른 버전은 HTTP 409이며 저장하지 않습니다. 직원 업무 문서는 기존 필수 `version` 권한 해시 검사를 유지하며 새 화면은 `expectedEditVersion`도 전송합니다. 구버전 직원 화면은 기존 해시로 보호되지만, 구버전 관리자·근로자 화면은 입력을 복사한 뒤 새로고침해야 저장할 수 있습니다.

기본서류 PUT은 `expectedEditVersion` 외에 최신 조회 응답의 `basic_version`을 `expectedBasicVersion`으로 반드시 보내야 합니다. 이 값의 누락·불일치는 HTTP 409이며 저장하지 않습니다. 구버전 화면이나 외부 API 호출자도 이 필드를 추가해야 하며, 삭제 후 같은 문서 ID가 재사용되어도 이전 편집으로 새 문서를 덮을 수 없습니다.

버전은 DB 쓰기 잠금 안에서 비교하며 초 단위 수정 시각에 의존하지 않습니다. 본문·상세 변경, 서명·첨부·결재선·결재 이력·참조자·교육 대상 변경 때 해당 문서의 버전이 증가합니다. 다른 문서의 추가나 수정은 영향을 주지 않습니다. 자신의 열린 편집 화면에서 첨부나 서명을 별도로 저장한 경우에도 409가 날 수 있습니다. 입력은 유지되므로 필요한 내용을 복사하고 문서를 다시 열어 확인한 뒤 수정하세요. 자동 병합이나 자동 최신 버전 재저장은 하지 않습니다.

기존 DB에는 기본값 0인 열과 트리거만 트랜잭션으로 추가합니다. 기존 본문·상세·서명·이력은 수정하지 않습니다. 기본서류의 필수 `expectedBasicVersion`을 제외하면 서버 내부의 기존 `Store.updateDocument` 호출은 버전 생략을 계속 허용하지만 이는 신뢰된 내부 호출의 호환 정책이며 외부 관리자·근로자 API는 생략을 허용하지 않습니다. 새로운 외부 수정 경로를 추가할 때도 조회 버전을 필수로 전달해야 합니다.

승인된 위험성평가 개선 정보 `PUT /api/documents/:id/risk-improvement`도 조회 당시 `edit_version`을 `expectedEditVersion`으로 반드시 전달합니다. 단건 `{siteId, expectedEditVersion, index, dueDate, completionDate, responsible}`와 일괄 `{siteId, expectedEditVersion, changes:[{index, dueDate, completionDate, responsible, previous:{dueDate, completionDate, responsible}}]}` 모두 적용됩니다. 버전 누락·잘못된 형식·불일치와 일괄 이전값 불일치는 HTTP 409이며 전체 요청을 저장하지 않습니다. 값이 원상복귀된 경우에도 이전 버전은 거절됩니다. 이전 단일 객체 형식의 위험성평가는 index 0으로 수정할 수 있습니다. 저장 잠금 안에서 관리자 세션을 재확인하며, 충돌 시 화면 입력은 유지됩니다. 필요한 입력을 복사한 뒤 문서를 다시 열어야 합니다.

### 근로자 작업중지·위험신고 작성 세션

`POST /api/worker/work-stops`와 `POST /api/worker/hazard-reports`는 작성 화면을 열 때 받은 로그인 또는 `/api/worker/session` 응답의 `reportContext`를 그대로 전송해야 합니다. 계정·현장·세션 세대를 현재 요청 쿠키와 DB 저장 잠금 안에서 비교합니다. 다른 탭의 계정 전환과 같은 계정 재로그인 후에는 이전 화면의 요청을 저장하지 않습니다. 세대 값은 쿠키의 단방향 파생값이며 인증 수단이 아닙니다. 응답은 `no-store`이고 화면 메모리에서만 사용합니다.

컨텍스트 누락·불일치는 HTTP 409입니다. 구형 화면과 외부 API 호출자도 필수 필드를 추가해야 합니다. 입력 내용을 복사한 뒤 다시 로그인해 새 화면에서 확인하고 제출하세요. 서버 거절 시 폼을 초기화하거나 새 계정 컨텍스트로 자동 재전송하지 않습니다. 로그아웃을 시작하거나 화면이 제거되면 사진 읽기 완료 후 전송도 중단합니다. 기존 세션 폐기·현장 차단·사진 형식/크기·익명 저장 규칙은 유지됩니다. 내부 Store 호출의 인터페이스와 기존 데이터는 변경하지 않습니다.

### 결재 회차 충돌 방지 API

일반 결재자의 `POST /api/reviewer/documents/:id/decision` 및 `/comments`, 관리자의 `POST /api/documents/:id/transition` 중 승인·반려·전결 요청에는 화면에서 조회한 문서의 `approval_cycle_id`를 `expectedCycleId`로 전송한다. `POST /api/documents/batch-approve`는 `ids`와 같은 순서와 길이의 `expectedCycleIds` 배열을 전송한다. 누락, 숫자가 아닌 값, 다른 회차는 HTTP 409이며 구버전 외부 클라이언트도 예외가 없다. 일괄 요청은 한 항목만 불일치해도 모두 취소한다. 오류 시 의견·서명·선택은 화면에 남으므로 입력을 보관하고 문서를 다시 조회하여 내용을 확인한다.

검증은 쓰기 잠금 획득과 세션 재확인 후, 상태·서명·이력을 변경하기 전에 수행한다. 기존 내부 Store 호출에 한해서 마지막 회차 인수를 생략한 호출을 호환하며, HTTP 경계는 누락을 항상 `null`로 정규화하므로 JSON 입력으로 이 호환 경로에 진입할 수 없다. 회차가 없는 과거 자료는 다시 상신하여 회차를 생성한 뒤 처리한다.

### 작성자 상태 변경·서명 충돌 방지 API

관리자 `POST /api/documents/:id/transition` 및 근로자 `POST /api/worker/documents/:id/transition`의 `submit`, `withdraw`, `revise` 요청은 화면에서 조회한 문서의 정수 `edit_version`을 `expectedEditVersion`으로 보낸다. 관리자 작성자 서명 경로 `checklist-signature`, `tbm-signature`, `joint-signature`, `meeting-signature`와 근로자 작업계획서 `author-signature` 저장에도 필수다. 작업계획서 서명 조회 응답은 `editVersion`을 함께 제공한다. 작업계획·참조 문서의 기존 `expectedVersion` 해시도 그대로 필요하다.

쓰기 잠금 획득 후 세션·작성 권한을 다시 확인하고 편집 버전을 비교한다. 누락·형식 오류·과거 버전은 HTTP 409이며 상태·결재 회차·이력·현재/이전 서명을 변경하지 않는다. 실패한 화면은 입력과 서명을 지우거나 최신 버전으로 자동 재전송하지 않는다. 구형 화면과 외부 API 호출자는 새 필드를 추가하고 문서를 다시 열어 내용을 확인해야 한다. 내부 Store 직접 호출만 버전 인수 생략 호환을 유지한다.

직원 작성 업무 문서의 상태 변경·서명은 기존 필수 `version` 해시가 문서 편집 버전·서명·결재 이력을 포함하며 쓰기 잠금 안에서 검사한다. 근로자 TBM 작성자 서명도 기존 필수 교육 `expectedVersion` 해시가 문서 편집 버전·대상·첨부·서명을 포함한다. 두 경로에는 별도 필드를 중복 요구하지 않는다. 관리자 승인·반려 및 일괄 승인에는 기존 결재 회차 검사를 그대로 사용한다.

신청 정보는 로컬 SQLite DB의 `sticker_requests`에 삭제할 때까지 보존합니다. `신청·개인정보 삭제`는 해당 신청 행을 삭제하며 기존 백업 사본은 별도로 관리해야 합니다. 전체 DB 백업·복원에 신청 정보도 포함됩니다. 관리자만 접근하며 근로자·시험 결재자 화면에는 제공하지 않습니다. 시험에는 가상 개인정보만 사용하세요.

API는 `GET/POST /api/sites/:siteId/sticker-requests`, `PUT/DELETE /api/sites/:siteId/sticker-requests/:id`입니다. 변경과 삭제에는 조회 시 받은 `version`이 필수이며 충돌은 HTTP 409입니다. 쓰기 잠금 획득 후 관리자 세션을 재검사하고, 현장과 신청 ID를 함께 검증합니다. 현장을 바꾸면 신청 창을 닫고 이전 현장의 늦은 응답을 버립니다. 충돌 시 목록을 새로고침한 후 내용을 확인하고 다시 처리하세요.

### 근로자 나머지 저장 요청의 화면 세션

출역 관리, 보호구 수령, 작업지시 응답, 출입 복원·퇴근과 근로자 문서 수정·상신·첨부 삭제·교육 대상·TBM 및 작성자 서명도 최초 화면의 `reportContext`를 JSON 본문에 전송합니다. 작업지시 사진과 문서 첨부 업로드는 같은 객체를 `JSON.stringify`한 `X-Worker-Report-Context` 헤더를 전송합니다. 바이너리 본문은 그대로 유지합니다. 컨텍스트 누락·불일치·잘못된 헤더는 HTTP 409와 `sessionChanged: true`로 거절하며 DB 잠금 획득 후에도 다시 검사합니다. 로그인은 기존 방식으로 새 컨텍스트를 발급하고, 기존 로그인 복원은 최초 세션 조회에서 받은 컨텍스트를 사용합니다. 현장 접속 차단 이후에도 유효한 기존 세션의 퇴근을 허용하는 정책은 유지합니다.

### 자주 묻는 질문(FAQ)

게시판의 `자주 묻는 질문`은 공지·시스템 공지·커뮤니티와 분리된 `faq` 종류입니다. 조회 분류는 전체·서비스이용·결제이며 검색어(제목·본문)와 분류를 함께 적용합니다. 관리자는 서비스이용 또는 결제를 지정해 작성합니다. 새 글은 기본 관리자 전용이며 `시험 계정에 공개`를 선택한 글만 모든 현장의 직원 시험 계정에서 조회합니다. 직원은 FAQ 글을 작성·수정·삭제할 수 없으며, 공개 글의 댓글과 첨부 열람은 기존 게시판 정책을 따릅니다. 저장과 권한은 이 프로젝트의 명시적 정책을 따릅니다.

기존 DB에는 분류 열을 자동 추가하며 기존 글과 공개 설정을 보존합니다. 분류를 보내지 않는 구형 관리자 수정 요청도 기존 FAQ 분류를 유지합니다. 신규 FAQ의 분류 생략 기본값은 서비스이용입니다. 직접 분류 등록은 현재 제공하지 않습니다. 시험에는 가상 데이터만 사용했습니다.

검증: `node --test test/faq.test.js test/board*.test.js test/community.test.js`. FAQ DB 이관·HTTP 권한·검색·분류·첨부·댓글·수정 충돌 및 관리자/직원 화면 대역을 포함합니다. 화면 대역은 실제 브라우저 시각 검증을 대신하지 않습니다.

FAQ 페이지 이동은 관리자와 직원 화면에서 권한·분류·검색을 적용한 결과를 10건씩 표시합니다. 이전·다음 및 현재/총 페이지를 제공하며 분류·검색·게시판 변경 시 첫 페이지로 돌아갑니다. 마지막 페이지의 글이 삭제되면 남아 있는 페이지로 조정합니다. 페이지마다 10건을 표시합니다.

FAQ 상단 안내는 관리자가 선택하는 J웹의 독립 정책입니다. 선택한 FAQ를 등록 ID 내림차순으로 검색·분류·페이지와 관계없이 먼저 표시하며 일반 10건 페이지에서 중복 제외합니다. 상단 안내 선택은 공개 설정을 변경하지 않습니다. 기존 글은 기본 해제이며 구형 수정의 속성 생략은 기존 선택을 보존합니다. 단일 `/api/faq-posts` 및 `/api/reviewer/faq-posts` 조회가 권한을 적용한 상단 안내와 필터 결과를 함께 반환하며 기존 전체 목록 API는 유지합니다.

## 관리자 개인 계정

전역 관리자 메뉴에서 개인별 아이디와 이름을 추가하고 이름 변경, 중지·재개, 암호 초기화, 모든 세션 종료, 전역/현장 제한 권한과 현장 배정을 관리합니다. 새 계정 폼은 현장 제한·빈 배정으로 시작합니다. 전역 선택 시 개별 배정은 저장하지 않습니다. 마지막 활성 전역 관리자는 중지하거나 현장 제한으로 전환할 수 없습니다. 권한·배정이 실제로 바뀌면 해당 계정의 모든 세션이 종료되므로 다시 로그인해야 합니다. 서버가 오래된 계정 버전이나 마지막 전역 관리자 변경을 거절하면 입력창에 오류를 표시합니다.

현장 제한 화면에는 서버가 `/api/sites`로 반환한 배정 현장만 표시합니다. 현재 UI에서 지원하는 기능은 문서 목록과 제목·본문 요약 조회, 교육·TBM의 세부 항목과 첨부 조회, 위험성평가 상세·현재 활동 및 그 첨부 조회, 체크리스트 상세 조회, 안전 점검·순회 점검·안전 업무 일지 상세와 첨부 조회, 합동 안전점검·노사협의체·안전간담회 상세와 첨부 조회, 작업계획서 기본정보·장비·장구·장소·작업자·안전대책·장비 점검과 첨부 조회, 작업허가서 기본정보·연결 자료·안전대책·사전 점검·연장과 첨부 조회, 일반 공지 임시저장·수정, 근로자 기본정보 목록·등록·수정, 날짜별 출역 조회·등록·수정과 공수 수정, 장비 출역 대장입니다. 근로자 면허 이름·번호는 전역 화면과 같은 행 편집기로 등록·수정·삭제합니다. 최대 20행, 각 100자이며 둘 다 빈 행은 제외하고 모든 행을 삭제하면 빈 배열로 저장합니다. 면허 항목을 생략하는 이전 API 요청은 기존 값을 보존합니다. 자기 등록 근로자 기본정보를 저장하면 기존 동작대로 일반등록으로 전환됩니다. 급여·계정·개별 가입정보, 교육·TBM·위험성평가·체크리스트·안전 점검·순회 점검·안전 업무 일지·합동 안전점검·노사협의체·안전간담회·작업계획서·작업허가서·재해 보고서 이외 문서의 세부 서식과 교육·TBM·작업계획서·체크리스트·안전 점검·순회 점검·안전 업무 일지·합동 안전점검·노사협의체·안전간담회·작업허가서·재해 보고서 이외 문서의 첨부, 시험 연장·결재 서명 외 서명·결재 처리·다른 문서 작성은 이 화면에서 지원하지 않습니다. 전체 현장 통계, 전역 계정·게시판·AI, 현장 추가 등 미지원 메뉴는 숨깁니다. 현장 전환 시 이전 입력창을 닫고 이전 응답·전송을 차단합니다. 서버가 저장을 거절하면 현재 입력창을 보존하여 내용을 복사할 수 있습니다. 배정이 비면 자료를 요청하지 않고 전역 관리자에게 배정을 요청하도록 안내합니다. 현장 자체의 중지 상태 필드는 없으며 계정 중지와 배정 제거를 사용합니다. 이 메뉴 숨김은 서버 권한 검사를 대체하지 않습니다. 기존 기록의 개인 작성자 식별은 제공하지 않습니다.

관리자·발주처·결재자는 역할별 주소·계정 각각 최대 10,000개 기록을 보관합니다. 상한에 도달하면 만료 전 기존 기록을 삭제하지 않고 새 주소 또는 계정의 인증을 429로 거절합니다. 따라서 주소와 아이디를 분산해 기록을 밀어내는 우회는 막지만, 대규모 공격으로 기록이 포화되면 아직 기록되지 않은 정상 사용자의 로그인도 최대 5분 지연될 수 있습니다. 기존 로그인 세션에는 영향을 주지 않습니다. 동일 NAT·프록시를 쓰는 사용자는 주소 제한을 공유합니다. 분산 공격과 다중 서버 운영에는 별도의 공유 제한·트래픽 방어가 필요합니다.

### 직원·발주처 시험 계정 이메일 찾기

이 기능은 기본적으로 꺼져 있습니다. 이메일 전달 서비스가 설정되면 직원은 로그인 후 내 정보에 이메일을 저장하고 **계정 찾기용 이메일 확인**을 선택합니다. 전달된 링크를 15분 안에 열어 확인한 이메일 하나를 계정에 연결합니다. 같은 이메일을 두 직원 계정에 동시에 확인할 수 없습니다. 이후 직원 로그인 화면의 **아이디·암호 찾기**에 이름과 확인한 이메일을 입력하면 해당 이메일로 시험 아이디와 15분간 유효한 암호 변경 링크를 보내도록 요청합니다. 주민등록번호는 받지 않습니다.

발주처는 가입할 때 저장한 이메일을 로그인 후 **계정 찾기용 이메일 확인**으로 확인합니다. 이후 발주처 로그인 화면의 **아이디·암호 찾기**에서 아이디 찾기는 이름과 가입한 휴대전화, 암호 찾기는 아이디와 가입한 휴대전화를 입력하고 확인한 이메일을 함께 적습니다. 휴대전화는 공백·하이픈·더하기 기호를 제외한 숫자로 비교합니다. 발주처끼리는 같은 이메일을 동시에 확인할 수 없으며 직원 계정과는 별도로 관리합니다. 가입 이메일을 잘못 입력한 경우 관리자에게 문의하세요.

링크는 한 번만 사용할 수 있습니다. 새 암호를 설정하면 해당 계정의 기존 세션이 종료되고 이메일 확인도 해제되므로 로그인 후 다시 확인해야 합니다. 이메일 주소, 계정 활성 상태 또는 암호가 바뀌면 이전 확인과 링크는 무효가 됩니다. 백업 사본에도 이메일 확인 상태와 미사용 링크는 포함하지 않습니다. 주소 확인 전에 암호를 잊었거나 이메일을 사용할 수 없으면 관리자에게 재설정을 요청하세요.

서버 설정에는 아래 세 값이 필요합니다. 이메일 전달 주소는 아래 형식의 요청을 받아 실제 메일을 보내는 별도 서비스 또는 호환 어댑터여야 합니다. 일반 SMTP 서버를 그대로 지정하는 방식은 아닙니다. 설정한 HTTPS 공개 주소를 링크에 사용하며, HTTPS 외의 전달 주소는 `localhost`, `127.0.0.1`, `::1` 시험 서버만 허용합니다. 전달 비밀값은 공백 없는 16~256자의 인쇄 가능한 영문 기호·숫자입니다. 비밀번호나 전달 비밀값은 소스·Git·채팅에 넣지 마세요.

```powershell
$env:JWEB_PUBLIC_ORIGIN = 'https://jweb.example.com'
$env:JWEB_RECOVERY_DELIVERY_URL = 'https://mail.example.com/send'
$env:JWEB_RECOVERY_DELIVERY_TOKEN = [System.Net.NetworkCredential]::new('', (Read-Host '이메일 전달 비밀값' -AsSecureString)).Password
npm start
```

전달 서비스에는 `Authorization: Bearer <비밀값>`과 JSON `{ "to": "수신 이메일", "subject": "제목", "text": "본문" }`을 POST합니다. 성공 응답은 접수로만 취급하며 실제 수신을 보장하지 않습니다. 서비스에는 이메일 주소와 시험 아이디, 확인 또는 암호 변경 링크가 전달되지만 암호는 전달하지 않습니다. 전송 실패는 자동 재시도하지 않고, 계정 찾기 요청은 존재 여부와 관계없이 같은 안내를 표시합니다. 같은 계정에는 1분에 한 번만 새 링크를 만들며 요청 제한은 프로세스별로 적용되고 재시작 또는 다른 서버와 공유되지 않습니다. 발송 중 서버가 종료되면 메일이 전달되지 않을 수 있습니다.
